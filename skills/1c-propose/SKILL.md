# Предложить правило или рецепт в tiny1C

Цель: превратить то, что узнали в этой задаче, в файл правила или рецепта по шаблону набора,
не вынеся в него ничего лишнего. Правило рождается из пойманной ошибки, а не из
желания написать правило. Ничего не отправляется автоматически: результат -
файл и «конверт», который человек передаёт дальше.

## 1. Найди кандидатов

Пройди по этой сессии и выпиши кандидатов в две корзины. Правило - подходит под одно из трёх:

- ошибка платформы или инструмента, которую разбирали дольше одной попытки;
- правило из `checklist` не сработало или его не хватило;
- поведение платформы не по ожиданию (удивление), у которого есть причина.

Рецепт - порядок действий, который добыт: первая попытка не сработала или порядок
неочевиден; он годится для любой базы; каждый шаг проверен в этой сессии.
Получилось с первого раза по документации - не рецепт.

Для каждого кандидата-правила сначала проверь `lookup_rule` (дословный текст ошибки),
для кандидата-рецепта - `lookup_guide` (по задаче): если такое уже есть - это не
новое, максимум правка существующего.
Не бери: советы без проверки, пересказ документации или чужих наборов правил,
выводы, которые нечем соблюсти или опровергнуть.

Нет ни одного кандидата - так и скажи и остановись.

## 2. Спроси человека

По каждому кандидату: одна строка («что сломалось - почему - как правильно») и
вопрос, брать ли его. Дальше - только взятые. Уточни у человека то, чего не
видно из сессии: дату и как именно поймано (проект называй обобщённо).

## 3. Собери файл

Шаблон правила - `${CLAUDE_PLUGIN_ROOT}/tracks/_TEMPLATE.md`, рецепта -
`${CLAUDE_PLUGIN_ROOT}/tracks/_GUIDE_TEMPLATE.md`; прочитай нужный. Файл правила -
один на правило, в каталоге `${CLAUDE_PLUGIN_DATA}/proposals/` под именем
`<тема>-XXX.md` (тема - `bsl`, `forms`, `mdo`, `query`, `tmpl`, `workflow`...;
настоящий номер присвоит приёмщик). Поля:

- `id`: `<тема>-XXX`, `направление`: `core` (или код конфигурации, если правило
  верно только для неё), `категория` и `серьёзность` - из словарей шаблона и
  `${CLAUDE_PLUGIN_ROOT}/CONTRIBUTING.md`, `платформы`: где проверено;
- `заголовок` - одна фраза: что нельзя или что надо;
- `ключи` - слова, по которым правило будут искать, **включая текст ошибки
  дословно**;
- `источник` - `ошибка:<проект обобщённо> ГГГГ-ММ-ДД, где поймано` (или другой
  вид: `измерение:`, `эксперимент:`, `образец:`, `решение:`, `документация:`);
- `check` - список «вид:описание», вид только из словаря: `lint`, `checkconfig`,
  `checkconfig-ext`, `smoke-forms`, `smoke-samples`, `smoke-print`, `fixtures`,
  `refcheck`, `xml-audit`, `manual`. Не знаешь, чем ловится, - честный
  `manual:` с описанием, как смотрит человек;
- тело: разделы Симптом (текст ошибки дословно), Причина, Правило, Как проверить,
  История.

Рецепт - тоже один файл на рецепт, `${CLAUDE_PLUGIN_DATA}/proposals/how-XXX.md`.
Поля: `id: how-XXX`, `направление`, `категория`, `платформы`, `заголовок`,
`источник` (`практика:<проект обобщённо> ГГГГ-ММ-ДД, где проверено`; стоит сразу
после заголовка), `задача` (одна фраза: что получаем), `ключи`, `check`,
`правила` - список id правил, на которые рецепт опирается (найди их через
`lookup_rule` или `checklist`; рецепт ссылается на правила, а не пересказывает их).
Тело: `## Шаги` (нумерованный порядок), `## Проверка результата`,
`## Где ломается` (может быть пустым).

**Чистая комната.** Репозиторий публичный. В файле не должно быть: имён
заказчиков и контрагентов, номеров заявок и тикетов, адресов баз и серверов,
логинов и паролей, путей с именами пользователей, кусков кода и макетов типовых
конфигураций, персональных данных. Пиши своими словами, факты - свободны,
чужие формулировки и подборки - нет.

## 4. Проверь гигиену

```
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/hygiene.py" --файл "${CLAUDE_PLUGIN_DATA}/proposals/<файл>.md"
```

(на Windows - `python` вместо `python3`). Скрипт проверяет один файл вне
дерева (правило или рецепт - вид определяет сам): формат, словари, источник, check, имена заказчиков, пути, токены. Что
нашёл - исправь; затем перечитай файл сам и убери то, что скрипт знать не может
(названия проектов и организаций, внутренние номера).

## 5. Выдай «конверт»

Покажи человеку каждый готовый файл целиком, в формате CONTRIBUTING:

```
Файл: tracks/<направление>/rules/<тема>-XXX.md   (рецепт: tracks/<направление>/guides/how-XXX.md)
---
id: ...
...весь фронтматтер и текст...
```

Один файл - одно правило или один рецепт, целиком (не кусками). Скажи, куда файл сохранён, и
что дальше его передаёт человек: в «Базу знаний ИИ» портала TinyCIO, если он
работает в нём, либо владельцу набора. Сам ничего никуда не отправляй и не
коммить в чужие репозитории.
