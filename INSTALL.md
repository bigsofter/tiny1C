# Раскатка: как подключить tiny1C к агенту

Сервер работает по **stdio**: агент запускает его как обычный локальный
процесс и общается через стандартный ввод-вывод. Ничего не хостится — ни
портов, ни демона, ни аккаунта. Требуется только Python 3.8+; внешних
зависимостей у сервера нет.

Отсюда общий рецепт для любой системы, умеющей MCP:

```
транспорт: stdio
команда:   python3
аргументы: <путь к клону>/mcp/server.py
```

Всё остальное на этой странице — как записать эти три строки в конкретном
клиенте, и что делать там, где MCP не поддерживается вовсе.

---

## Claude Code

### Плагином (рекомендуется)

```bash
claude plugin marketplace add bigsofter/tiny1C
claude plugin install 1c@tinycio
```

Клонировать вручную не нужно: правила приезжают вместе с плагином, сервер
запускается из `${CLAUDE_PLUGIN_ROOT}/mcp/server.py`. После установки —
`/reload-plugins` либо новая сессия.

```bash
claude plugin update 1c        # обновить
claude plugin uninstall 1c     # убрать
```

### Клоном и файлом проекта

```bash
git clone https://github.com/bigsofter/tiny1C
```

`.mcp.json` в корне проекта:

```json
{
  "mcpServers": {
    "tiny1c": {
      "command": "python3",
      "args": ["${TINY1C_HOME:-../tiny1C}/mcp/server.py"]
    }
  }
}
```

Claude Code раскрывает `${VAR}` и `${VAR:-default}`, поэтому путь конкретной
машины не обязан попадать в общий репозиторий: задайте `TINY1C_HOME` в личных
настройках, а в проекте оставьте относительный путь по умолчанию.

Проверка — команда `/mcp` в сессии: сервер `tiny1c` должен быть в списке.
Обновление правил — `git pull` в клоне.

## OpenAI Codex CLI

Конфигурация — `~/.codex/config.toml` (или `.codex/config.toml` в доверенном
проекте):

```toml
[mcp_servers.tiny1c]
command = "python3"
args = ["/путь/к/tiny1C/mcp/server.py"]
```

То же самое одной командой:

```bash
codex mcp add tiny1c -- python3 /путь/к/tiny1C/mcp/server.py
```

Новую конфигурацию видит новая задача: список инструментов фиксируется на
старте.

## DeepSeek Harness (dsh)

Harness подключает MCP плагином `@deepseek-ai/dsh-mcp-client` — один плагин на
один сервер. В `cordis.yml` или в патч-файле (`cordis.patch.yml`):

```yaml
- id: mcp-tiny1c
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: tiny1c
    transport: stdio
    command: python3
    args: ['/путь/к/tiny1C/mcp/server.py']
```

Инструменты появятся под именами `mcp__tiny1c__lookup_rule`,
`mcp__tiny1c__checklist` и так далее. `serverName` менять не стоит: от него
зависят имена всех инструментов.

Проверка, что сервер поднялся:

```bash
dsh web --dump-config | grep -A3 mcp
```

Правка патч-файла подхватывается горячей перезагрузкой — перезапуск процесса
не нужен.

## Прочие MCP-клиенты

Cursor, VS Code, Cline, Continue, Zed, LibreChat и другие читают собственные
файлы конфигурации, но поля те же: команда, аргументы, иногда явный
`"type": "stdio"`. Различается в основном имя файла и корневой ключ (`mcpServers`
против `servers`) — сверьтесь с документацией своего клиента и подставьте:

```json
{ "command": "python3", "args": ["/путь/к/tiny1C/mcp/server.py"] }
```

Проверить сервер можно и без клиента:

```bash
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | python3 mcp/server.py
```

В ответ должен прийти JSON с семью инструментами.

## Системы без MCP

Веб-чаты, простые обёртки над API и закрытые песочницы MCP не умеют. Туда
правила заезжают текстом — выгрузкой:

```bash
scripts/export.py --направление core,greenfield --выход dist/rules.md
```

Получится свод: заголовок каждого правила, ключевые слова и чем оно ловится,
со ссылкой на файл с полным текстом (~24 КБ на весь набор). Его кладут в
системную подсказку, в файл проектных инструкций (`AGENTS.md`, `.cursorrules`)
или в «знания» ассистента.

Если контекст позволяет, `--полный` включает тексты правил целиком (~80 КБ):

```bash
scripts/export.py --полный --платформа 8.3 --выход dist/rules-8.3.md
```

Отбор по направлению и платформе экономит контекст: проекту на 8.3 незачем
правила про падения клиента 8.5.

Минус этого способа один и существенный: свод устаревает в момент выгрузки.
Обновляется он только повторным запуском, тогда как MCP всегда отдаёт текущее
состояние набора.

## Обновление

| Способ подключения | Обновление |
|---|---|
| плагин Claude Code | `claude plugin update 1c` |
| клон | `git pull` в каталоге клона |
| выгрузка текстом | повторный `scripts/export.py` |

Перезапускать агент после `git pull` не нужно: сервер читает манифест при
старте процесса, а процесс живёт ровно одну сессию.
