# Псевдоним таблицы, совпадающий с именем поля соседней таблицы, делает поле неоднозначным

## Симптом

Ошибка выполнения запроса «Неоднозначное поле "Представления.Ссылка"» (в локали клиента —
«Campo ambiguo»), хотя каждое поле в тексте квалифицировано псевдонимом. В EDT и при
CheckConfig запрос проходит: ошибка только на выполнении.

## Причина

Псевдоним одной таблицы соединения совпадает с именем поля другой. Тогда
`Псевдоним.Ссылка` платформа читает двояко: поле таблицы с таким псевдонимом или
поле-ссылка внутри одноимённого поля соседней таблицы. Два пойманных случая:

- `Реквизиты` (ПВХ) + её табличная часть под псевдонимом `Представления`: у главной
  таблицы есть поле-табличная часть `Представления`, и `Представления.Ссылка` — либо
  присоединённая таблица, либо `Реквизиты.Представления.Ссылка`;
- `Справочник.Номенклатура КАК Номенклатура` + табличная часть техкарты, у которой есть
  поле `Номенклатура` (сырьё): `Номенклатура.Ссылка` — либо главная таблица, либо
  `ТехнологическаяКарта.Номенклатура.Ссылка`.

```bsl
// НЕПРАВИЛЬНО: псевдоним = имя табличной части главной таблицы
"... ИЗ ПланВидовХарактеристик.ДопРеквизиты КАК Реквизиты
|	ЛЕВОЕ СОЕДИНЕНИЕ ПланВидовХарактеристик.ДопРеквизиты.Представления КАК Представления
|	ПО Представления.Ссылка = Реквизиты.Ссылка"

// ПРАВИЛЬНО: псевдоним не совпадает ни с одним полем соединяемых таблиц
"...	ЛЕВОЕ СОЕДИНЕНИЕ ПланВидовХарактеристик.ДопРеквизиты.Представления КАК Заголовки
|	ПО Заголовки.Ссылка = Реквизиты.Ссылка"

// НЕПРАВИЛЬНО: у ТехнологическаяКарта есть поле Номенклатура
"ИЗ Справочник.Номенклатура КАК Номенклатура
|	ЛЕВОЕ СОЕДИНЕНИЕ Справочник.Номенклатура.ТехнологическаяКарта КАК ТехнологическаяКарта
|	ПО Номенклатура.Ссылка = ТехнологическаяКарта.Ссылка"

// ПРАВИЛЬНО
"ИЗ Справочник.Номенклатура КАК Продукция ... ПО Продукция.Ссылка = ТехнологическаяКарта.Ссылка"
```

## Как проверить

Псевдонимы всех таблиц соединения сверить с именами полей остальных таблиц запроса
(реквизиты, табличные части, измерения). Особенно опасны псевдонимы по имени объекта
(`КАК Номенклатура`, `КАК Контрагент`): такие поля есть почти у любой табличной части.
Прогоном ловится смоком форм, если запрос выполняется при открытии, и тестами
проведения уровня 3, если он в проведении.

## История

maERP 2026-09-08: запрос `УправлениеСвойствами.СвойстваОбъекта` заголовков дополнительных
реквизитов по языку; карточка номенклатуры не открывалась. Псевдоним переименован в 2.0.14.22.
Тем же днём тесты уровня 3 поймали второй случай в `ТоварыВНаличии.КоэффициентыТехкарт`:
проведение выпуска продукции и поступления из переработки падало. После переименования
первого псевдонима упал второй: `КАК ТехнологическаяКарта` против табличной части
`Номенклатура.ТехнологическаяКарта`. Переименовывать все псевдонимы запроса сразу
(2.0.14.25–26).
