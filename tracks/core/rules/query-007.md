# Функция общего модуля в выражении вычисляемого поля СКД падает на первой строке данных, а пустой отчёт формируется

## Симптом

Отчёт открывается и формируется — пока в выбранном периоде нет данных. Как только
появляется хотя бы одна строка, формирование падает:

```
Ошибка вывода результата
  по причине: Ошибка получения данных
  по причине: Ошибка в выражении
  [ОшибкаНастроекКомпоновкиДанных]
  по причине: Синтаксическая ошибка "ОбщегоНазначенияВызовСервера.РассчитатьКоэффициентЕдиницы"
```

Проверка конфигурации, смок «открыть все формы» и прогон всех вариантов отчётов с
пустыми параметрами молчат: выражение вычисляемого поля разбирается только тогда,
когда компоновке есть что вычислять.

## Причина

В `<calculatedField><expression>` стоит вызов функции общего модуля
(`ОбщегоНазначенияВызовСервера.РассчитатьКоэффициентЕдиницы(...)`), у которого
выставлен флаг «Вызов сервера». Компоновщик макета такую функцию в выражении не
принимает — «Синтаксическая ошибка» с именем функции. Передача
`ПроверятьДоступностьФункций = Ложь` в `КомпоновщикМакетаКомпоновкиДанных.Выполнить`
ошибку не снимает (проверено на 8.5.1).

```xml
<!-- неправильно: функция модуля «вызов сервера» в выражении -->
<calculatedField>
  <dataPath>ОборотКг</dataPath>
  <expression>Количество * Номенклатура.ВесЗнаменатель
    * ОбщегоНазначенияВызовСервера.РассчитатьКоэффициентЕдиницы(Номенклатура.ВесЕдиница, ЕдиницаИзмеренияВеса)</expression>
</calculatedField>

<!-- правильно: то же значение считает запрос набора, поле объявлено в наборе -->
<!-- запрос: ВЫБОР КОГДА Т.Номенклатура.Единица.ТипИзмеряемойВеличины = ЗНАЧЕНИЕ(Перечисление.ТипыИзмеряемыхВеличин.Вес)
              ТОГДА Т.КоличествоОборот ИНАЧЕ Т.КоличествоОборот * Т.Номенклатура.ВесЗнаменатель КОНЕЦ КАК ОборотКг -->
<field xsi:type="DataSetFieldField">
  <dataPath>ОборотКг</dataPath>
  <field>ОборотКг</field>
</field>
```

## Правило

Выражения вычисляемых полей и ресурсов СКД — только встроенные функции языка
выражений компоновки и поля схемы. Расчёт, которому нужен код, переносится в запрос
набора; если запросом не выразить — в модуль отчёта (`ПриКомпоновкеРезультата`,
внешний набор данных). Функцию общего модуля в выражении не использовать.

## Как проверить

Прогон вариантов с пустыми параметрами этого не ловит. Нужен сценарий, который
формирует отчёт на своих данных: провести документ в транзакции теста, выставить
отбор варианта на его место хранения или контрагента, скомпоновать в коллекцию
значений и сверить вычисляемое поле с ожидаемым числом. Статически — grep по
`<expression>` всех `Template.dcs` на «`Модуль.Функция(`».

## История

maERP, 2026-10-03, этап «Склад» перестройки меню. Вариант «Отчет по списанию
товаров» отчёта «Движения товара» чинили по query-006 (поля старого регистра),
ревью заметило, что «Оборот (кг)» для невесового товара даёт вес одной единицы
без количества. Правку умножением в выражении сценарий уровня 3 с проведённым
списанием уронил «Синтаксической ошибкой» на функции модуля «вызов сервера»; смок
со всеми вариантами отчётов и до, и после правки проходил — в его периоде
движений не было. Падение воспроизведено компоновкой схемы с настройками варианта
(`КомпоновщикМакетаКомпоновкиДанных`) в сценарии; формирование из формы отчёта на тех же
данных отдельно не проверялось. Расчёт перенесён в запрос набора, функция-коэффициент
(заглушка, всегда 1) из выражения ушла без изменения чисел.
