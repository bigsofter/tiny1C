# Загруженное расширение неактивно, пока флажок «Активно» не поставлен

## Симптом

Расширение загружено, `CheckModules -Extension` чист («Синтаксических ошибок не
обнаружено!»), `UpdateDBCfg -Extension` вернул код 0. А код расширения в сеансе не
выполняется: обработчик `&После("ПриНачалеРаботыСистемы")` не вызван, файл-маркер не
появился. Тот же симптом «правка не видна» бывает при ошибке компиляции (см. ext-001).

## Причина

Расширение, созданное из файлов (или из `.cfe`), осталось неактивным. Ключа командной
строки для активации у `1cv8 DESIGNER` в наблюдении не нашли; другие способы, например
`ibcmd`, не проверялись.

## Правило

- Активация - отдельный шаг: флажок «Активно» в Конфигураторе (Конфигурация, Расширения
  конфигурации) либо в режиме 1С:Предприятие.
- Флажок сохранялся при последующих перезагрузках расширения из файлов: в наблюдении его
  поставили один раз на расширение.
- Свойство `Активно` объектов `РасширенияКонфигурации.Получить()` записываемое (плюс метод
  `Записать()`). В наблюдении из кода расширения, выполнявшегося в безопасном режиме,
  `Записать()` падало: «Изменение расширения конфигурации недоступно в безопасном режиме».
  Из кода основной конфигурации программная активация не проверялась.
- Молчание хука при чистой проверке модулей - сначала проверять активность расширения.

## Как проверить

Флажок в списке расширений; в сценарии - чтение `Активно` у нужного расширения.

## История

2026-10-12, песочница на копии базы. Расширение, созданное из файлов, хук не
исполнило, соседнее ранее активированное - исполнило в том же сеансе. Предположение,
что загрузка новой версии активного расширения сбрасывает флажок, сначала записали
как наблюдение, а потом опровергли: после многократных перезагрузок оба расширения
исполняли свои хуки.
