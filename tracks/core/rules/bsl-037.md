# Значение в составной реквизит: проверять состав типов

## Симптом

Запись документа падает «Несоответствие типов» при присваивании ссылки в реквизит составного
типа, и это не ловится статически. В наблюдении падала запись всего документа.

## Причина

Наборы типов у двух реквизитов одного документа могут сильно различаться (в примере
из переноса: одно основание допускает четыре типа, а аналогичный реквизит строки расшифровки
двадцать семь). Найденная по идентификатору ссылка может быть корректной ссылкой своей базы,
но её типа в наборе именно этого реквизита нет. В какой именно строке кода (присваивание,
копирование свойств, обработчик записи) упало, в источнике не установлено.

## Правило

Либо сверять тип заранее, либо защищаться:

```bsl
// ПРАВИЛЬНО
Если Метаданные.Документы.<Документ>.Реквизиты.<Реквизит>.Тип.СодержитТип(ТипЗнч(Значение)) Тогда
    Объект.<Реквизит> = Значение;
Иначе
    // в протокол: тип не допустим
КонецЕсли;
// или присваивание в Попытка с записью в протокол
```

Перед переносом сверять составы типов обоих целевых реквизитов с составом типов источника.

## Как проверить

Прогон переноса на документе, ссылающемся на тип, которого нет в наборе целевого реквизита;
статически не ловится - только сверкой составов типов глазами.

## История

2026-09-25, перенос платёжных документов УТ 10 в БП: значение, тип которого есть в БП,
но отсутствует в наборе типов этого реквизита, роняло запись всего документа.
