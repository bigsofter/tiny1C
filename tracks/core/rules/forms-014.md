# Стандартные команды формы документа зависят от свойства «Проведение»: включили проведение — WriteAndClose ломает загрузку

## Симптом

Обновление базы из EDT (или загрузка конфигурации) падает целиком:

```
Error de descargar/subir la configuración
Nombre incorrecto del comando del elemento de formulario. - Form.StandardCommand.WriteAndClose
```

По-русски — «Неверное имя команды элемента формы». Объект и форма в тексте не
названы. EDT проект валидирует без замечаний, CheckConfig до загрузки не доходит.

## Причина

Набор стандартных команд формы документа определяется свойством «Проведение».
У документа с запрещённым проведением есть «Записать и закрыть»
(`WriteAndClose`), а команд проведения нет. У документа с разрешённым проведением —
наоборот: есть `Post`, `PostAndClose`, `UndoPosting`, а `WriteAndClose` нет.

Кнопка с явной стандартной командой хранится в `Form.form` строкой
`<commandName>Form.StandardCommand.WriteAndClose</commandName>`. Когда документу
включают проведение, строка остаётся, и ссылка становится недействительной во
**всех** формах документа — в том числе в формах, которые задача не трогала.

## Правило

Меняя свойство «Проведение» документа, проверить стандартные команды во всех его
формах. Если у проводимого документа нужна кнопка «Записать и закрыть» (например,
у вида операции, который не проводится), делать её **своей командой формы**:

```bsl
&НаКлиенте
Процедура ЗаписатьИЗакрыть(Команда)
	Если Записать() Тогда
		Закрыть();
	КонецЕсли;
КонецПроцедуры
```

и кнопку `<commandName>Form.Command.ЗаписатьИЗакрыть</commandName>` (команда формы
с обработчиком в `<formCommands>`). Обратное тоже верно: у документа с запрещённым
проведением не ставить явные кнопки `Post`, `PostAndClose`, `UndoPosting`.

## Как проверить

Машинно — сверкой: для каждого документа прочитать «Проведение» из `.mdo` (в EDT
тег `<posting>Deny</posting>` пишется только при запрете, умолчание — разрешено) и
найти в формах документа запрещённые для этого значения стандартные команды. В
maERP это часть `scripts/refcheck.py`; на состоянии до исправления сверка находит
обе кнопки.

## История

2026-09-14, maERP. Этап E6 разрешил проведение заказа клиента и добавил в основную
форму явные кнопки: для продажи главная — «Записать и закрыть» стандартной командой
`WriteAndClose`. Такая же кнопка годами стояла в форме ECommerce, которую задача
менять запрещала. Ревью кода, данных и безопасности, смок по коду и проверка
заполнения не видели ошибки: база до загрузки не обновлялась. Владелец получил отказ
загрузки при обновлении из EDT — сборки 2.0.15.14 и 2.0.15.15 не ставились. Обе
кнопки переведены на свою команду формы (2.0.15.16), в `refcheck` добавлена сверка.
