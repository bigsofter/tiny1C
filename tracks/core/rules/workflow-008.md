# Ожидание процесса 1С по подстроке командной строки цепляет посторонние процессы

## Симптом

Пакетный шаг (`CheckConfig`, клиент с `/C "СмокТест;..."`) давно записал результат в
файл `/Out` или отчёт, а скрипт продолжает ждать до таймаута и в конце снимает
«процесс» `pkill`-ом. Итог шага — ложное «не завершился за N с», при этом сам
результат в файле чистый. Заодно гибнет то, что скрипт принял за процесс 1С.

## Причина

На macOS обёртка `1cv8` отдаёт работу дочернему процессу, поэтому код возврата не
используется и завершение ждут по `pgrep -f "<подстрока>"`. Голая подстрока вроде
`CheckConfig` или `СмокТест;` есть и в командных строках других процессов: наблюдателя
логов (`grep "Замечания CheckConfig"`), редактора с открытым скриптом, второй
консоли. `pgrep` находит их, ожидание не заканчивается, `pkill` их убивает.

```bash
# НЕПРАВИЛЬНО
while pgrep -f "$1" >/dev/null; do sleep 5; done
pkill -f "$1"

# ПРАВИЛЬНО: только командные строки платформы
while pgrep -f "1cv8.*$1" >/dev/null; do sleep 5; done
pkill -f "1cv8.*$1"
```

## Как проверить

Если шаг «висит» при готовом файле результата — `ps -ef | grep <подстрока>` покажет,
кого на самом деле ждёт скрипт. В скриптах прогона все паттерны `pgrep`/`pkill`
должны начинаться с `1cv8`.

## История

maERP 2026-09-08: `scripts/run-lib.sh` ждал `CheckConfig` голой подстрокой; наблюдение
за логом прогона содержало её в фильтре `grep`, шаг 1 смока ждал 900 с, результат
«ошибок нет» был готов с первых минут, а наблюдатель был снят `pkill`-ом (exit 144).
Паттерны привязаны к `1cv8`.
