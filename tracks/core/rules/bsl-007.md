# Тип значения вида характеристики обязан быть подмножеством типа плана

## Симптом

При программном создании элемента плана видов характеристик падает присваивание
`Объект.ТипЗначения = ...` с текстом «Тип не является подмножеством типа значений
плана видов характеристик» (в локали клиента — «El tipo no es un subconjunto...»).
В конфигураторе и при CheckConfig ошибки нет — только на выполнении.

## Причина

У плана задан составной тип значения с квалификаторами (например Число 15,3 и
Строка 200). Тип отдельного вида характеристики должен целиком помещаться в него.
`Число(15,2)` шире `Число(15,3)` по целой части (13 разрядов против 12), безразмерная
`Строка` шире `Строка(200)` — оба отвергаются.

```bsl
// НЕПРАВИЛЬНО: план - Число(15,3), Строка(200)
Новый ОписаниеТипов("Число", Новый КвалификаторыЧисла(15, 2))
Новый ОписаниеТипов("Строка")

// ПРАВИЛЬНО: квалификаторы в пределах плана, строку брать из типа плана
Новый ОписаниеТипов("Число", Новый КвалификаторыЧисла(14, 2))
ТипПлана = Метаданные.ПланыВидовХарактеристик.ДополнительныеРеквизиты.Тип;
Новый ОписаниеТипов("Строка", , ТипПлана.КвалификаторыСтроки)
```

## Как проверить

Каждое `ОписаниеТипов`, которое попадает в `ТипЗначения` вида характеристики, сверить с
`<type>` плана в `.mdo`: целая часть числа, длина строки, состав ссылочных типов.
Прогоном — тест, создающий вид характеристики с каждым используемым типом.

## История

maERP 2026-09-08: реквизит «Площадь» отрасли «Строительство» описан как Число(15,2)
при типе плана Число(15,3); умолчание `Новый ОписаниеТипов("Строка")` тоже было вне
плана. Ловилось бы сценарием уровня 3 «Отрасль», но прогон на базе не делался.
