# У справочника с длиной наименования 0 поля Наименование нет — запись в него падает

## Симптом

При программном создании элемента `Объект.Наименование = "..."` падает с «Поле объекта
недоступно для записи (Наименование)» (в локали клиента — «El campo del objeto no
disponible para guardar»). Стандартный реквизит `Description` при этом в `.mdo` есть.

## Причина

Длина наименования у справочника 0 (в EDT-формате тег `descriptionLength`
отсутствует — это и есть 0). Стандартный реквизит объявлен всегда, но при нулевой длине
платформа его не хранит и не даёт присвоить. Такие справочники именуются другим
реквизитом (у договоров maERP — `Описание`), и свой код конфигурации заполняет именно его.

```bsl
// НЕПРАВИЛЬНО: у ДоговорыСКонтрагентами наименования нет
Договор.Наименование = "Договор поставки";

// ПРАВИЛЬНО: тот реквизит, которым объект именует сам справочник
Договор.Описание = "Договор поставки";
```

## Как проверить

`grep descriptionLength <справочник>.mdo`: нет тега — наименования нет. Как объект
именуется на самом деле — смотреть в модуле менеджера или форме элемента справочника.
Прогоном ловится любым тестом, который создаёт элемент программно.

## История

maERP 2026-09-08: помощник `НовыйДоговор` тестов документов ставил `Наименование`,
все десять сценариев падали на подготовке данных. Переведён на `Описание`, как в
`Справочники.ДоговорыСКонтрагентами.СоздатьДоговор`.
