# Заимствованная форма в выгрузке расширения

Справка по устройству файлов. Формат - выгрузка Конфигуратора. Имена в примерах вымышленные.

## Состав

- Стаб `<Объект>/Forms/<Форма>.xml`: `ObjectBelonging=Adopted`, `ExtendedConfigurationObject`,
  в `InternalInfo` запись `xr:PropertyState` со свойством `Form` и состоянием `Extended`,
  тип формы `Managed`.
- `<Объект>/Forms/<Форма>/Ext/Form.xml`: рабочее дерево и `<BaseForm version="2.21">` с
  отступом на один уровень больше.
- `Ext/Form/Module.bsl` только у доработанных форм; в нём только код расширения, базового
  кода нет.
- В `ConfigDumpInfo.xml` пара записей: форма и «форма.Form» (идентификатор с суффиксом `.0`).

## Нетронутая и доработанная форма

- Нетронутая: рабочее дерево равно BaseForm (разница только в отступе), нет `<Events>`,
  `<Commands>` и модуля.
- Доработанная состоит из дельты двух видов: блок `<Events>` с указанием момента вызова
  (`callType` Before, After или Override) и процедурами расширения, и добавленные
  элементы с путями данных `Объект.<Реквизит расширения>` и кнопками на команды.
- `<Attributes>` рабочего дерева объявляет основной реквизит `Объект` (`MainAttribute`,
  `SavedData`) и добавленные колонки табличных частей; он есть и в BaseForm, дельта - только
  колонки.

## Команды и id

Новая команда расширения получает `id=1000000`, действие записывается как
`<Action callType="After">`. У типовых команд id в рабочем дереве перенумерованы (в
наблюдавшейся форме сдвиг 1000001 на 1000002), а их `callType="Before"` есть только в
BaseForm. При ручной правке id сверять с выгрузкой Конфигуратора, не придумывать (см. forms-018
про коллизию id в EDT-формах).

## История

2026-10-09, разбор выгрузки работающего расширения для БП 3.0: малая форма документа с
дельтой событий и большая форма с добавленными полями и командой. Собственных
реквизитов формы (не объекта) в образце не было.
