# Вывод «объект нигде не используется» — только по полному поиску, без обрезки вывода

## Симптом

В разведке объект признан мёртвым («ни один модуль не читает, ни один документ не пишет»), владелец
по этому выводу решает его удалить, а при подготовке удаления находятся чтение в тексте запроса и
запись движениями документа.

## Причина

Поиск по всему проекту выдаёт десятки строк, и вывод обрезают (`| head`). Первыми идут файлы прав
ролей — по ним объект упоминается в каждой роли, — и до модулей и `.mdo` документов список не
доходит. Вторая ловушка — в zsh `grep --include=*.bsl` без кавычек падает на раскрытии шаблона,
и поиск по модулям молча не выполняется.

Ссылка на регистр в запросе — строка (`РегистрСведений.<Имя>.СрезПоследних`), запись — элемент
`registerRecords` в `.mdo` документа. Ни то ни другое не видно по составу подсистем и меню.

## Правило

1. Перед выводом «не используется» — полный поиск без обрезки: `git grep -c <Имя> -- src` (счётчик
   по файлам), затем просмотр каждого файла, кроме прав ролей.
2. Отдельно проверить три места: тексты запросов в `.bsl`, `registerRecords` и `content` опций в
   `.mdo`, формы и макеты.
3. В отчёте о выводе указать команду поиска и число файлов, а не только заключение.

## Как проверить

Перед тем как передать владельцу «объект мёртв» — команда и её полный результат в плане. Ошибочный
вывод ловит сверка ссылок после удаления (`refcheck`), но это уже после решения владельца.

## История

2026-10-03, maERP. В разведке раздела «Продажи» поиск по регистру надбавок обрезали `head`: показались
только роли и опция, вывод «мёртвый» ушёл в план, техдолг и отчёт. Владелец распорядился удалить
регистр. Полный поиск при подготовке удаления нашёл чтение в расчёте базовых цен правил
ценообразования и запись документом «Корректировка регистров». Удаление остановлено, вывод исправлен
в документах, вопрос возвращён владельцу.
