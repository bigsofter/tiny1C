# Ограничение «Условие» у поля СКД не прячет поле от отбора компоновщика

## Симптом

Отчёт строит внешний набор из строк двух сортов: детальные (обслуживание с видом и
причиной) и служебные (фонд времени станка, у которых вид и причина пусты). Показатель
делит одно на другое. Общий отбор пользователя «Вид = Ремонт» убирает служебные строки,
знаменатель становится нулём, процент — нулём.

Попытка закрыть это в схеме — поставить полю набора `useRestriction/condition = true` —
не помогает: на 8.5.1 после такой правки `КомпоновщикНастроек.Настройки.Отбор.ДоступныеПоляОтбора.НайтиПоле(...)`
поле по-прежнему находит, и программно (а через сохранённые настройки — и у пользователя)
отбор по нему ставится.

## Причина

Общий отбор компоновки применяется к каждой детальной записи набора без разбора её
«сорта». Ограничение поля в схеме — подсказка интерфейсу настроек, а не запрет компоновке;
проверять его надо на базе, а не выводить из названия.

## Как правильно

Разобрать отбор кодом до компоновки (`ПриКомпоновкеРезультата`): элементы по полям
детальных строк перенести в отбор данных набора (служебные строки добавлять после него),
в настройках компоновки их выключить; отборы, которые так не перенести, выключить и
назвать пользователю. Отбор по полю, которое есть у всех строк (станок), оставить
компоновке. Поведение закрепить сценарием, а не ограничением схемы.
