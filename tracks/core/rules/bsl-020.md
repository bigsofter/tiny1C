# ПоказатьВыборИзСписка и ПоказатьВыборЭлемента — методы формы: в общем модуле их вызывают через форму

## Симптом

Код, перенесённый из модуля формы в клиентский общий модуль, не компилируется: «Процедура или функция с указанным
именем не определена (ПоказатьВыборИзСписка)». В модуле формы тот же вызов без квалификатора работал. Серверные
сценарии уровня 3 при этом проходят — клиентский модуль они не компилируют; ловят проверка конфигурации и смок.

## Причина

`ПоказатьВыборИзСписка`, `ПоказатьВыборЭлемента`, `ВыбратьИзСписка` — методы объекта `ФормаКлиентскогоПриложения`,
а не глобального контекста. В модуле формы они вызываются без квалификатора, потому что контекст модуля — сама форма.
У общего модуля такого контекста нет. Глобальные соседи (`ПоказатьВопрос`, `ПоказатьПредупреждение`,
`ПоказатьВводЗначения`, `ОткрытьФорму`) вызываются где угодно, отсюда ложное ощущение, что все «Показать…» глобальные.

## Правило

1. Клиентская процедура общего модуля, которой нужен список выбора, принимает форму параметром и вызывает
   `Форма.ПоказатьВыборИзСписка(Оповещение, Список, Элемент)`.
2. Цель `ОписаниеОповещения` в общем модуле — имя самого модуля (`Новый ОписаниеОповещения("Имя", МойМодульКлиент,
   Контекст)`), процедура экспортная.
3. После переноса кода из модуля формы в общий модуль — CheckConfig до передачи на базу.

## История

maERP 2026-09-22, этап S7 (подбор номенклатуры): показ короткого списка «последние созданные + выбрать из
справочника» вынесен из двух форм в `РаботаСДокументамиКлиент.ПоказатьПодборНоменклатуры`. Линтер и сверки молчали,
сценарии уровня 3 прошли; смок остановился на CheckConfig с ошибкой компиляции общего модуля. Лечение — параметр
`Форма` и вызов через него.
