# Переименование локального метода модуля ловит только проверка конфигурации

## Симптом

Метод переименован, вызовы поправлены — по грепу, который нашёл «все» места. Статический анализ
чист, сверка ссылок чиста. Прогон тестов **не падает, а зависает**: клиент стартует, пишет маркер
старта и больше ничего не делает, отчёта нет.

В журнале клиента при интерактивном запуске:

```
Ошибка инициализации модуля: Обработка.<Имя>.МодульМенеджера
по причине:
{Обработка.<Имя>.МодульМенеджера(3775,11)}: Процедура или функция с указанным именем не определена (<СтароеИмя>)
```

## Причина

Вызовы локального (не экспортного) метода внутри своего же модуля видит только компилятор
платформы. Статический анализатор о неопределённом методе молчит; сверка ссылок на метаданные
смотрит экспортные методы общих модулей, а не внутримодульные вызовы.

Модуль, который не компилируется, «падает» не там, где его правили: прогон упирается в первое
обращение к нему и остаётся без внятного сообщения — со стороны это выглядит как зависание.

## Правило

После переименования любого метода — проверка конфигурации, а не только линтер и сверка ссылок.
Перед этим — греп по СТАРОМУ имени по всей конфигурации, включая модуль, в котором метод живёт:
вызовы одного метода редко выглядят одинаково (`Возврат Имя();` и `?(Условие, Имя(), "")` в одном
модуле), и шаблон, написанный по первому найденному месту, второе пропускает.

## Как проверить

Проверка конфигурации (`CheckConfig`) — компиляция модулей. Это единственный машинный гейт, который
такую ошибку видит.

## История

maERP, 2026-09-20. Функция текста сообщения в модуле менеджера обработки переименована при обобщении
механизма на второй тип документа-основания. Замена шла по точному шаблону вызова, а шаблонов
оказалось два: один с тернарным оператором, два — просто `Возврат Имя();`. Линтер и сверка ссылок
дали чисто, прогон уровня 3 завис на двадцать минут без единой строки в отчёте, и причину искали в
только что написанном сценарии. Текст ошибки компиляции пришёл только из интерактивного запуска.
