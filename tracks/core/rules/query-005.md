# Параметр схемы компоновки без userSettingID не виден на форме и не ставится программно: отчёт выходит пустым

## Симптом

Отчёт формируется без ошибок и показывает пустой результат на базе, где данные
заведомо есть. На форме отчёта нет полей, которыми этот отбор задают: панель
быстрых настроек пуста или в ней только отборы. Программная установка параметра
из кода молча ничего не делает — исключения нет, значение остаётся прежним.

Ни один статический гейт ошибку не видит: XML схемы корректен, запрос
синтаксически верен, проверка конфигурации молчит, смок «открыть все формы»
проходит — форма отчёта открывается, просто пустая.

## Причина

В схеме компоновки у параметра два разных места:

* `<parameter>` в теле схемы — объявление: имя, тип, значение по умолчанию,
  выражение;
* `<dcsset:dataParameters>` внутри варианта настроек — то, что попадает в
  настройки, а с тегом `<dcsset:userSettingID>` — ещё и в **пользовательские**
  настройки.

Форма отчёта показывает `КомпоновщикНастроек.ПользовательскиеНастройки`. Параметр,
объявленный только в теле схемы, в эту коллекцию не попадает: пользователь его
не видит и не меняет. Значение берётся из умолчания схемы, а умолчание у даты —
пустая дата. Условие вида

```
ГДЕ Документ.Дата МЕЖДУ &НачалоПериода И &КонецПериода
```

превращается в «дата между пустой датой и пустой датой» и не пропускает ни одной
строки. Отчёт формально работает.

Та же коллекция — единственная точка входа для кода, который готовит настройки
перед `ОткрытьФорму`: перебор `ПользовательскиеНастройки.Элементы` в поисках
`ЗначениеПараметраНастроекКомпоновкиДанных` по такому параметру не находит
ничего и завершается без ошибки.

```xml
<!-- неправильно: параметр объявлен, но в настройки не выведен -->
<parameter>
  <name>НачалоПериода</name>
  ...
</parameter>
<!-- в dcsset:settings элемента dcsset:dataParameters нет вовсе -->

<!-- правильно: параметр периода выведен в пользовательские настройки -->
<dcsset:dataParameters>
  <dcscor:item xsi:type="dcsset:SettingsParameterValue">
    <dcscor:parameter>ПериодОтчета</dcscor:parameter>
    <dcscor:value xsi:type="v8:StandardPeriod">...</dcscor:value>
    <dcsset:userSettingID>9989496f-3f06-4878-8d07-e51c174841bf</dcsset:userSettingID>
    <dcsset:userSettingPresentation .../>
  </dcscor:item>
</dcsset:dataParameters>
```

## Правило

Параметр схемы, который задаёт пользователь или код, выводится в
`dcsset:dataParameters` с собственным `userSettingID` и представлением на всех
языках конфигурации. Границы периода в пользовательские настройки не выводят по
одной: заводится параметр типа `СтандартныйПериод`, а `НачалоПериода` и
`КонецПериода` делаются вычисляемыми от него (`&ПериодОтчета.ДатаНачала`,
`&ПериодОтчета.ДатаОкончания`) с `useRestriction = true` — пользователь получает
привычный выбор периода, а запрос — две границы.

Пустой период при этом обязан означать «вся история», а не «ничего»: конец
периода задаётся выражением с запасной датой, иначе незаполненный период снова
даёт пустой отчёт.

```
Выбор Когда ЗначениеЗаполнено(&ПериодОтчета.ДатаОкончания)
  Тогда &ПериодОтчета.ДатаОкончания
  Иначе ДатаВремя(3999, 12, 31, 23, 59, 59)
Конец
```

Тип даты у таких параметров — `DateTime`, а не `Date`: у `СтандартныйПериод`
конец периода равен 23:59:59, и квалификатор «Дата» срежет время, потеряв
документы последнего дня.

Выражение параметра не ссылается само на себя: `НачалоПериода(&НачалоПериода,
"ДЕНЬ")` — не «округлить введённое значение», а рекурсия, которой в схеме делать
нечего.

## Как проверить

Машинной проверки нет. После правки схемы — grep по `Template.dcs`: у каждого
параметра, который должен задавать пользователь, есть строка
`dcsset:userSettingID` в блоке `dcsset:dataParameters`.

Смок «открыть все формы» этот класс ошибок не ловит принципиально: форма
открывается. Ловит только формирование отчёта на базе с данными — пустой
результат там, где строки заведомо есть.

## История

maERP, 2026-09-24. В отчёт «История товара» (объединение строк десяти товарных
документов) добавили отбор по периоду: параметры `НачалоПериода` и
`КонецПериода` в теле схемы, условие `МЕЖДУ` в каждой части объединения. В
настройки варианта параметры не вывели. Отчёт открывался, но всегда был пустым —
и из меню отчётов, и по команде «Товар → История товара» со строки документа.

Команда из документа заодно показала вторую грань правила: общий код установки
настроек искал параметры в `ПользовательскиеНастройки.Элементы` и не находил их,
так что период «последние 12 месяцев» не доезжал до отчёта — молча, без единого
сообщения.

Рядом в той же конфигурации лежали три отчёта с правильным устройством периода
(`ПериодОтчета` типа `СтандартныйПериод` в `dataParameters`), по которым отчёт и
починили. Заодно всплыли остатки экспериментов: `use = Always` и
самоссылающиеся выражения `НачалоПериода(&НачалоПериода, "ДЕНЬ")`.
