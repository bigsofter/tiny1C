# Языки в Form.form — соседние теги, а не несколько key/value внутри одного

## Симптом

Подпись поля выводится на языке разработки во всех интерфейсах, хотя в
`Form.form` переводы на месте и лежат рядом с русским. EDT импортирует форму
молча, проверка конфигурации проходит.

## Причина

Локализованная строка в исходниках EDT — это **несколько братских тегов**, у
каждого своя пара `key`/`value`:

```xml
<!-- правильно -->
<title>
  <key>ru</key>
  <value>Наценка, %</value>
</title>
<title>
  <key>fr</key>
  <value>Majoration, %</value>
</title>
```

Если пары сложить внутрь одного тега, читается только первая, остальные
отбрасываются:

```xml
<!-- неправильно: платформа возьмёт только ru -->
<title>
  <key>ru</key>
  <value>Наценка, %</value>
  <key>fr</key>
  <value>Majoration, %</value>
</title>
```

Схема такую форму принимает, поэтому потери не видно ни при импорте, ни в
проверке конфигурации: строка просто теряет языки.

Так получается при правке XML скриптом или руками «по образцу»: переводы
дописывают к существующему блоку, не заметив, что блок надо повторить целиком.
Это та же ошибка, что forms-003 — правка по подстроке вместо проверенной
позиции узла.

## Правило

Каждый язык — отдельный тег целиком. Тот же порядок действует для `synonym` в
`.mdo`, `toolTip`, `presentation` в списках выбора и `content` в надписях.

После правки XML скриптом узел перечитывается: в теге локализованной строки
ровно один `key` и один `value`.

## Как проверить

Греп по `.form` и `.mdo`: тег вида `<X>…</X>`, внутри которого встречается
больше одного `<key>`. Законных случаев нет.

## История

2026-09-24, maERP. Сплошная сверка локализации нашла две формы — заказ
покупателя и реализация товаров и услуг, — где подпись «Наценка, %» была
записана четырьмя парами внутри одного `<title>`. Во французском, английском и
испанском интерфейсе колонка подписывалась по-русски. Остальные 1500 проверенных
наборов локализованных строк по конфигурации были оформлены правильно, так что
ошибка редкая, но глазами в диффе не видна: блок выглядит полным.
