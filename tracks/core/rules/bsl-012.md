# Метод у выражения «Новый Тип(...)» сразу не вызывается

## Симптом

Модуль не компилируется, клиент при первом обращении к модулю показывает окно:

```
Ошибка инициализации модуля: Обработка.ТестыДокументов.МодульМенеджера
{Обработка.ТестыДокументов.МодульМенеджера(4038,38)}: Неизвестный оператор
    Выборка = Новый Запрос(ТекстЗапроса)<<?>>.Выполнить().Выбрать();
{…(4038,39)}: Обнаружено логическое завершение исходного текста модуля
[ОшибкаКомпиляцииВстроенногоЯзыка]
```

На испанском интерфейсе — `La sentencia desconocida` и `Se ha encontrado un final lógico del texto original del
módulo`. BSL LS строку не отмечает: выражение для него синтаксически допустимо. Headless-прогон, который открывает
форму с этим модулем, просто не дожидается старта клиента, а окно с ошибкой висит на экране.

## Причина

Во встроенном языке `Новый Тип(...)` — отдельная конструкция, а не выражение, у которого можно взять член: после
закрывающей скобки конструктора точка недопустима. Цепочки работают только у результата вызова метода или у
переменной (`Запрос.Выполнить().Выбрать()`).

## Правило

Объект сначала присваивается переменной, методы вызываются у неё.

```bsl
// НЕПРАВИЛЬНО
Выборка = Новый Запрос(ТекстЗапроса).Выполнить().Выбрать();

// ПРАВИЛЬНО
Запрос = Новый Запрос(ТекстЗапроса);
Выборка = Запрос.Выполнить().Выбрать();
```

## Как проверить

- До передачи на базу — поиск `Новый \w+\([^)]*\)\.` по изменённым модулям.
- CheckConfig с проверкой модулей или любой прогон, компилирующий модуль (смок, тесты документов), падает с позицией
  строки и столбца.

## История

maERP 2026-09-14, этап E11 «демо-набор»: в помощнике сценария уровня 3 запрос создавался и выполнялся одной строкой.
Линтер и сверка ссылок прошли чисто; ошибку показал клиент прогона тестов на копии базы с частично загруженными
модулями — «Клиент не стартовал за 120 с», а на экране владельца висело окно инициализации модуля.
