# Устройство ConfigDumpInfo.xml расширения

Справка. Формат - выгрузка Конфигуратора (`DumpConfigToFiles`), атрибут формата
`Hierarchical`, версия 2.21.

## Три формы записей

- Объект верхнего уровня: `name="Класс.Имя"`, `id` и `configVersion` (40 шестнадцатеричных знаков).
- Вложенный элемент (реквизит, табличная часть, команда): только `id`, без `configVersion`,
  записью внутри родителя.
- Объект и файл его содержимого: две верхние записи, `Класс.Имя` и `Класс.Имя.Form`
  (или `.Template`, `.Rights`), у второй `id` вида `<uuid>.0`.

Исключение - подсистемы: каждый уровень вложенности идёт отдельной верхней записью со
своим `configVersion`.

## Практический вывод

Составлять или править манифест вручную бессмысленно: платформа сама строит его при выгрузке,
а для загрузки из файлов он не нужен (см. ext-002: наличие или отсутствие в каталоге
результат не меняет). Брать манифест из свежей выгрузки, а не конструировать.

## История

2026-10-09, разбор выгрузки работающего расширения для БП 3.0 (платформа 8.5.1.1529).
