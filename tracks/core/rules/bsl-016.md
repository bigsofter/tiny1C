# Вызов процедуры, удалённой из модуля, не ловит ни один статический гейт

## Правило

Заменяя в модуле не одну процедуру, а диапазон текста «от комментария до комментария»,
сверяй список процедур модуля до и после правки поимённо. BSL Language Server вызов
несуществующей процедуры **не диагностирует**: он разбирает модуль, но не резолвит
локальные вызовы. Сверка ссылок на объекты метаданных смотрит на строковые имена
объектов, а не на процедуры модуля. Первым такую правку ловит только CheckConfig,
то есть уже у владельца после импорта в EDT — или клиент на первой же записи объекта
сообщением «Процедура или функция с указанным именем не определена».

Механическая сверка:

```
git show HEAD:<файл> | grep -oE '^(Процедура|Функция) \w+' | sort > /tmp/было
grep -oE '^(Процедура|Функция) \w+' <файл>              | sort > /tmp/стало
diff /tmp/было /tmp/стало
```

Разница обязана совпадать с задуманной: удалено ровно то, что решено удалить, добавлено
ровно то, что решено добавить. Любая лишняя строка в диффе — снесённая заодно процедура.

Опаснее всего это в модулях объектов: там процедуры лежат подряд, разделённые только
комментариями, и диапазон «от заголовка А до заголовка Б» легко захватывает соседей,
которые к правке отношения не имеют.

## Самодельный гейт для сборок без компиляции

Для внешних обработок, где сборка BSL не компилирует (см. workflow-016), есть смысл завести
скрипт «внутренний вызов - объявление»: каждый вызов процедуры или функции без точки сверяется
с объявлениями этого же модуля и белым списком платформенных имён; новые платформенные
имена вносятся в белый список осознанно. Гейту нужна самопроверка-ловушка: модуль с вызовом
без объявления обязан валить сборку. Так была поймана процедура, пропавшая при правке: в
базе она дала бы «Процедура или функция с указанным именем не определена», а сборка
обработки её не видела.

## История

maERP 2026-09-19, модуль объекта `ЗаказПокупателя`. Правка заменяла блок нормализации
дерева материалов, диапазон был задан от одного комментария-заголовка до другого, и
вместе с блоком исчезли три соседние процедуры, которые вызывает `СогласоватьМатериалы`:
`ЕстьТехкартыСтрок`, `ОчиститьМатериалыЗаказаНеНаПроизводство`,
`РазвестиПовторныеКодыСтрокСМатериалами`. Линтер дал ноль новых замечаний, сверка ссылок
и проверка динамических списков прошли чисто. Любая запись заказа упала бы у владельца.
Поймал круг верификации ревью, а не гейт.

2026-09-17, сборка внешних обработок для базы на 1С:УНФ: гейт «внутренний вызов - объявление»
с самопроверкой поймал пропавшую при правке функцию до прогона в базе.
