# Локальная переменная не называется как свойство глобального контекста или общий модуль

## Симптом

Два лица одной ошибки.

1. Присваивание переменной с именем свойства глобального контекста (`Документы`,
   `Справочники`, `Константы`, `Метаданные`, `Обработки`…) падает во время выполнения:
   «Поле объекта недоступно для записи (Документы)» / `El campo del objeto no disponible
   para guardar`. CheckConfig и BSL LS молчат: для них это обычное присваивание.
2. Новый общий модуль получает имя, которое в других модулях уже занято локальными
   переменными (`Производство = Перечисления....Производство`). Эти модули перестают
   видеть переменную как переменную: присваивание имени общего модуля недопустимо.
   BSL LS ловит это правилом `CommonModuleAssign` — но только если линтер гонять по всей
   конфигурации, а не только по изменённым модулям.

Опасно именно в редких ветках: ошибка вылезает, когда до строки дошло выполнение. В
maERP переменная `Документы` стояла в подсказке к отказу проведения — вместо читаемого
отказа реализация падала исключением.

## Причина

Свойства глобального контекста и общие модули — имена верхнего уровня. Локальная
переменная их не перекрывает: `Документы = ...` — это попытка записать в свойство
глобального контекста, а после появления общего модуля `Производство` то же самое
происходит с переменной `Производство`.

```bsl
// НЕПРАВИЛЬНО
Документы = Запрос.Выполнить().Выгрузить().ВыгрузитьКолонку("Регистратор");
Производство = ПолучитьФункциональнуюОпцию("Производство"); // после появления общего модуля «Производство»

// ПРАВИЛЬНО
Регистраторы = Запрос.Выполнить().Выгрузить().ВыгрузитьКолонку("Регистратор");
УчетПроизводства = ПолучитьФункциональнуюОпцию("Производство");
```

## Как проверить

- Переменные называть по содержимому (`Регистраторы`, `ВидПроизводство`), а не
  собирательными словами, совпадающими с менеджерами коллекций.
- Перед созданием общего модуля с коротким «словарным» именем — поиск присваиваний
  `(^|[^.А-Яа-я])ИмяМодуля\s*=` по всем `.bsl` конфигурации и полный прогон BSL LS.
- Ветку с новой переменной должен пройти сценарий уровня 3: только выполнение ловит
  первое лицо ошибки.

## История

maERP 2026-09-14, этап E9 «автовыпуск при отгрузке»: полный прогон линтера после
создания общего модуля `Производство` показал `CommonModuleAssign` в тестах документов,
форме списка заказов клиента и форме заказа поставщику — переменные переименованы до
базы. Переменную `Документы` в `ПодсказкаСекунды` поймал только сценарий уровня 3 на
базе: последний шаг ждал отказа проведения по нехватке материалов, а получил исключение.
