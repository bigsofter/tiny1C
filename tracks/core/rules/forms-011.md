# Поле динамического списка попадает в ТекущиеДанные только через колонку таблицы

## Симптом

```
Object field not found (Ссылка)
{Обработка.АРМПроизводство.Форма.Форма.Форма(169)}:Заказ = ?(ТекущиеДанные = Неопределено,
```

Падает при активации строки или при выборе. Форма открывается нормально,
данные в таблице видны, ошибка приходит только когда обработчик строки читает
поле. CheckConfig и смок «открыть все формы» молчат: `ПриСозданииНаСервере`
отрабатывает, а обработчик строки - клиентский и выполняется у пользователя.

## Причина

`ТекущиеДанные` таблицы динамического списка - не строка запроса, а набор
полей, выведенных в таблицу колонками. Поля, которое запрос выбирает, но
таблица не показывает, там нет: ни видимой колонкой, ни скрытой - значит нет и
в `ТекущиеДанные`. Ключ строки при этом доступен всегда, но отдельно -
через `ТекущаяСтрока` элемента.

Ловушка обостряется, когда таблица строится программно: колонки перечисляются
в коде, и `Ссылка` в этот список легко не попасть - в отличие от формы,
собранной в конфигураторе, где ссылка обычно уже выведена.

## Правило

Поле, которое читает обработчик, выводится колонкой - скрытой, если показывать
его пользователю не нужно.

Неправильно:

```bsl
ДобавитьКолонкуСписка(ТаблицаЗаказов, "Номер");
ДобавитьКолонкуСписка(ТаблицаЗаказов, "Контрагент");
// ...
Заказ = Элемент.ТекущиеДанные.Ссылка;   // Поле объекта не обнаружено
```

Правильно:

```bsl
КолонкаСсылки = ДобавитьКолонкуСписка(ТаблицаЗаказов, "Ссылка");
КолонкаСсылки.Видимость = Ложь;
```

Второй рабочий путь - взять ключ строки, а не поле: `Элементы.Таблица.ТекущаяСтрока`
для списка возвращает ссылку и колонки не требует. Он же единственный, когда
нужного поля в запросе нет вовсе.

## Как проверить

Машинной проверки на это нет: поле берётся у `ТекущиеДанные`, а колонки могут
собираться в коде. Обратную сторону - колонку, под которой нет поля в запросе -
ловит статическая проверка списков (`listcheck` в maERP, вид проверки xml-audit). Саму ошибку ловит
только сценарий: открыть форму и встать на строку, то есть уровень UI-тестов.

## История

2026-09-09, maERP. Владелец сообщил об ошибке при щелчке по заказу в АРМ
производства. Таблица заказов строится программно, колонок восемь -
номер, дата, контрагент, статус, дата отгрузки, сумма, менеджер, комментарий;
`Ссылка` среди них не было, хотя запрос списка её выбирает. Соседняя таблица
связанных документов в той же форме работала: там `Ссылка` выведена колонкой и
служит единственным полем.

Диагноз подтвердил разбор соседних форм: три формы, где обработчик читает
`ТекущиеДанные.Ссылка`, оказались исправны - у них колонка есть, только записана
стандартным английским именем `Ref`.
