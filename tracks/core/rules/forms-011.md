# Поле динамического списка попадает в ТекущиеДанные через видимую колонку или «Использовать всегда»; ссылку брать из ТекущаяСтрока

## Симптом

```
Object field not found (Ссылка)
{Обработка.АРМПроизводство.Форма.Форма.Форма(169)}:Заказ = ?(ТекущиеДанные = Неопределено,
```

```
Object field not found (ЭтоГруппа)
{Справочник.Номенклатура.Форма.ФормаПодбора.Форма(8)}:Если ТекДанные = Неопределено Или ТекДанные.ЭтоГруппа Тогда
```

Падает при активации строки или при выборе. Форма открывается нормально,
данные в таблице видны, ошибка приходит только когда обработчик строки читает
поле. CheckConfig и смок «открыть все формы» молчат: `ПриСозданииНаСервере`
отрабатывает, а обработчик строки - клиентский и выполняется у пользователя.

## Причина

`ТекущиеДанные` таблицы динамического списка - не строка запроса, а набор
полей, выведенных в таблицу колонками, плюс поля с признаком «Использовать
всегда». Поля, которое запрос выбирает, но таблица не показывает и «всегда» не
просит, там нет. Ключ строки при этом доступен всегда, но отдельно - через
`ТекущаяСтрока` элемента.

**Скрытая колонка не спасает:** колонка, добавленная программно с
`Видимость = Ложь`, поле в `ТекущиеДанные` не положила (проверено 2026-09-13 в
maERP, та же ошибка в журнале регистрации).

**«Использовать всегда» - спасает.** Это не колонка, а свойство реквизита
списка: в Form.form оно записано отдельным узлом
`notDefaultUseAlwaysAttributes` с путём `<Список>.<Поле>` (узел перечисляет
поля, у которых признак отличается от значения по умолчанию, то есть как раз
включённые руками). Поле из этого списка приходит в `ТекущиеДанные`, не
занимая места в интерфейсе. Проверено 2026-09-25 в maERP на двух формах
одновременно: в форме списка договоров `Список.Ref` читается обработчиком,
колонки не имеет и лежит в этом узле - работает; в форме подбора номенклатуры
`ЭтоГруппа` колонки не имеет и в узле отсутствует - падает.

Ловушка обостряется, когда таблица строится программно: колонки перечисляются
в коде, и `Ссылка` в этот список легко не попасть - в отличие от формы,
собранной в конфигураторе, где ссылка обычно уже выведена.

## Правило

Ссылку строки списка с основной таблицей брать из ключа строки -
`Элемент.ТекущаяСтрока`: это сама ссылка, от состава колонок она не зависит.

Прочим полям, которые читает обработчик, выбрать один из двух способов - и
никогда не полагаться на скрытую колонку:

1. вывести поле **видимой** колонкой - если пользователю оно нужно;
2. отметить его **«Использовать всегда»** (`notDefaultUseAlwaysAttributes` в
   Form.form) - если нужно только коду.

Третий путь - не читать поле у строки вовсе, а получить его на сервере по
ключу строки. Он лучше двух первых, когда серверный вызов в обработчике всё
равно есть: правка Form.form дороже и рискованнее правки модуля (forms-003,
workflow-009), а лишнего обращения не появляется.

Неправильно:

```bsl
ДобавитьКолонкуСписка(ТаблицаЗаказов, "Номер");
ДобавитьКолонкуСписка(ТаблицаЗаказов, "Контрагент");
// ...
Заказ = Элемент.ТекущиеДанные.Ссылка;   // Поле объекта не обнаружено
```

Неправильно и после «исправления» (не работает):

```bsl
КолонкаСсылки = ДобавитьКолонкуСписка(ТаблицаЗаказов, "Ссылка");
КолонкаСсылки.Видимость = Ложь;
Заказ = Элемент.ТекущиеДанные.Ссылка;   // по-прежнему Поле объекта не обнаружено
```

Правильно:

```bsl
Заказ = Элемент.ТекущаяСтрока;
Если ТипЗнч(Заказ) <> Тип("ДокументСсылка.ЗаказПокупателя") Тогда
	Заказ = ПредопределенноеЗначение("Документ.ЗаказПокупателя.ПустаяСсылка");
КонецЕсли;
```

Правильно и для поля, которого в интерфейсе быть не должно - забрать его с
сервера по ключу строки, заодно тем же вызовом, что нужен обработчику:

```bsl
&НаКлиенте
Процедура СписокВыбор(Элемент, ВыбраннаяСтрока, Поле, СтандартнаяОбработка)
	СтандартнаяОбработка = Ложь;
	Если ТипЗнч(ВыбраннаяСтрока) <> Тип("СправочникСсылка.Номенклатура") Тогда
		Возврат;
	КонецЕсли;
	ДанныеСтроки = ДанныеСтрокиСписка(ВыбраннаяСтрока);   // один вызов сервера
	Если ДанныеСтроки.ЭтоГруппа Тогда
		Возврат;
	КонецЕсли;
	// ...
КонецПроцедуры
```

У списка без основной таблицы (например, по критерию отбора) ключ строки -
не ссылка; там поле выводится видимой колонкой.

## Как проверить

Машинной проверки на это нет: поле берётся у `ТекущиеДанные`, а колонки могут
собираться в коде. Обратную сторону - колонку, под которой нет поля в запросе -
ловит статическая проверка списков (`listcheck` в maERP, вид проверки xml-audit). Саму ошибку ловит
только сценарий: открыть форму и встать на строку, то есть уровень UI-тестов.

Разовый разбор конфигурации делается руками и стоит недорого: собрать по
модулям форм обращения `ТекущиеДанные.<Поле>`, оставить те, где таблица -
реквизит с `valueType types=DynamicList`, и для каждого поля посмотреть в
Form.form, есть ли у него видимая колонка или запись в
`notDefaultUseAlwaysAttributes`. Таблицы на реквизите-таблице значений под
правило не попадают.

## История

2026-09-09, maERP. Владелец сообщил об ошибке при щелчке по заказу в АРМ
производства. Таблица заказов строится программно, колонок восемь -
номер, дата, контрагент, статус, дата отгрузки, сумма, менеджер, комментарий;
`Ссылка` среди них не было, хотя запрос списка её выбирает. Соседняя таблица
связанных документов в той же форме работала: там `Ссылка` выведена колонкой и
служит единственным полем.

Диагноз подтвердил разбор соседних форм: три формы, где обработчик читает
`ТекущиеДанные.Ссылка`, оказались исправны - у них колонка есть, только записана
стандартным английским именем `Ref`.

2026-09-13, maERP. Исправление 2026-09-09 скрытой колонкой `Ссылка` не сработало:
журнал регистрации базы на следующей сборке показал ту же ошибку в той же строке.
Ссылка заказа переведена на `ТекущаяСтрока`, скрытая колонка убрана; владелец
подтвердил на клиенте, что активация и выбор строки работают. Правило переписано:
прежний совет «скрытой, если показывать не нужно» был неверен.

2026-09-25, maERP. Владелец прислал из журнала регистрации
«Object field not found (ЭтоГруппа)» в форме подбора номенклатуры. Форма
существовала с волны 9.4, и падала она не на группах, а при **любом** двойном
щелчке: `ЭтоГруппа` запрос списка выбирает, но колонки у поля нет и в
`notDefaultUseAlwaysAttributes` лежит только `Родитель`. То есть подбор не
работал ни разу с момента появления.

Исправлено третьим способом: признак группы берётся на сервере по
`ВыбраннаяСтрока` тем же вызовом, который и так возвращал характеристики
товара, - Form.form не тронут. Разбор остальной конфигурации (девять обращений
к `ТекущиеДанные`) других нарушений не нашёл; попутно выяснилось, что форма
списка договоров с тем же узором работает именно за счёт «Использовать всегда»,
и правило пополнилось вторым разрешённым способом.
