# Промежуточная очистка при перепроведении — теми же наборами `Движения`

## Симптом

Документ с режимом удаления движений «Удалять автоматически» перепроводится. Код
кладёт в `ДополнительныеСвойства` набора `Документ.Движения.<Регистр>` значение
(например, в подписке `ПередЗаписью` — прежние позиции регистратора, пока движения ещё
в базе), чтобы его прочитал модуль набора записей при записи новых движений. Модуль
набора видит это значение **дважды**: при пустой промежуточной очистке (до
`ОбработкаПроведения`) и при окончательной записи. Логика «свойство есть — значит,
окончательная запись» срабатывает и на очистке: побочный эффект удваивается.

## Причина

Перед `ОбработкаПроведения` платформа очищает прежние движения, записывая пустые наборы.
Это те же объекты `Движения` документа, а не новые наборы: их `ДополнительныеСвойства`
уже заполнены тем, что положил код до записи документа. Пустой набор у проведённого
регистратора бывает и окончательной записью (у документа не осталось строк по регистру),
так что одно «пусто и проведён» этапы тоже не различает.

## Как правильно

- Состояние для окончательной записи передавать через `ДополнительныеСвойства` наборов
  `Движения` (живёт вместе с объектом документа). Кэш общего модуля «на время вызова»
  для этого ненадёжен: платформа может вытеснить значение раньше конца вызова.
- Этапы различать флагом в переданной **структуре** (одна ссылка на все наборы, зеркальные
  наборы переносят ссылку): первая пустая запись после `ПередЗаписью` — промежуточная
  очистка, она ставит флаг; пустая запись после флага — окончательная.
- Значение сбрасывать в начале каждой записи документа: наборы `Движения` живут, пока
  жив объект, и снимок прошлой записи иначе дойдёт до следующей.
- Сценарий уровня 3 считает побочный эффект (оповещения, записи) — «ровно один раз», и
  отдельно проверяет окончательную запись пустого набора.
