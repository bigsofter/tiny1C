# Максимум id по коллекции формы считается по тегу с атрибутами, иначе новый id занят

## Симптом

Скрипт добавил в форму команду (или элемент) и выдал ей id «максимум по коллекции
плюс один». Номер оказался уже занятым: в коллекции две записи с одним `<id>`.
Молчат все проверки — EDT форму принимает, конфигуратор не ругается, прогон
«открыть все формы» её открывает. Последствие то же, что у forms-001: команда
теряется или привязывается не к своему обработчику, и видно это только глазами
на клиенте.

## Причина

Записи одной коллекции в `Form.form` не обязаны быть записаны одинаково. EDT
пишет их как `<formCommands>`, но запись, прошедшая через выгрузку конфигуратора
или чужую правку, несёт объявление пространства имён прямо на себе:

```xml
  <formCommands>                                              <!-- обычная запись -->
    <name>СтраницаНазад</name>
    <id>6</id>
  </formCommands>
<formCommands xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance">   <!-- та же коллекция -->
    <name>СоздатьЗаказПоПредложению</name>
    <id>8</id>
  </formCommands>
```

Поиск по строке `<formCommands>` вторую запись не видит. Максимум получается 7
вместо 8, и новая команда получает занятый номер 8.

## Правило

Искать записи коллекции регулярным выражением, допускающим атрибуты, а не
подстрокой с закрывающей скобкой.

Неправильно:

```python
блоки = re.findall(r'<formCommands>.*?</formCommands>', текст, re.S)
```

Правильно:

```python
блоки = re.findall(r'<formCommands(?:\s[^>]*)?>.*?</formCommands>', текст, re.S)
```

То же относится к `<items>`, `<attributes>`, `<parameters>`: правило про
раздельные пространства id (forms-001) выполняется только тогда, когда
пространство прочитано целиком.

## Как проверить

Машинной проверки в платформе нет. После вставки — собрать пары «имя, id» всей
коллекции и убедиться, что номера не повторяются; расхождение числа открывающих
и закрывающих тегов (`grep -c '<formCommands>'` против `grep -c '</formCommands>'`)
выдаёт такую запись сразу.

## История

maERP 2026-09-24: скрипт добавлял в 42 формы списка кнопки пагинатора «в начало»
и «в конец» вместе с командами формы. В 41 форме номера легли верно, в списке
заказов покупателя новая команда получила id 8, уже занятый командой создания
заказа по предложению. Нашлось состязательным ревью диффа, а не проверками:
сверка id по коллекциям в проекте не автоматизирована. Первое подозрение —
ошибка в самом расчёте максимума — отпало: расчёт был верен, он просто не видел
одну запись. Несовпадение счётчиков открывающих и закрывающих тегов (9 против 10)
оказалось тем признаком, по которому запись с атрибутом находится за секунду.
