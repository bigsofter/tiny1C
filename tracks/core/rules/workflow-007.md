# Пути с «ё»/«й» в git — только в NFC: NFD с macOS ломает проект на Windows и дублирует файлы

## Симптом

1. Клон репозитория на Windows: в навигаторе EDT часть объектов серая (регистры,
   отчёты, общие модули с «ё»/«й» в имени), при обновлении базы — ошибки SDBL
   по полям и таблицам этих объектов.
2. На macOS: коммит правки в модуле с «ё»/«й» в пути показывает в
   `git show --stat` весь файл как новый, а исходный остаётся изменённым.

## Причина

macOS отдаёт имена с составными буквами в разложенном виде (NFD: «е» +
комбинирующий знак), имена в `Configuration.mdo` и набранные руками — составные
(NFC). APFS их не различает, git и NTFS — различают. Попавший в индекс NFD-путь
на Windows становится каталогом, имя которого не совпадает с именем объекта в
`Configuration.mdo`: EDT объекта не находит. На macOS `git add <NFC>` рядом с
отслеживаемым NFD-путём даёт дубликат.

## Правило

- В индексе git пути только в NFC. В репозитории на macOS —
  `git config core.precomposeunicode true` (git сам приводит имена из файловой
  системы к NFC).
- Автоматическая проверка: ни одного пути из `git ls-files`, у которого
  `unicodedata.normalize("NFC", p) != p`. В maERP — в начале `scripts/lint.sh`.
- Уже попавшие NFD-пути переименовать в индексе без изменения содержимого:
  `git update-index --force-remove <NFD>` и
  `git update-index --add --cacheinfo <mode>,<sha>,<NFC>` (на macOS `git mv`
  не поможет — для файловой системы это одно имя). Коммит — только переименования,
  `0 insertions, 0 deletions`.

## Как проверить

```bash
git -c core.quotepath=false ls-files -z | python3 -c 'import sys,unicodedata;\
print(sum(unicodedata.normalize("NFC",p)!=p for p in sys.stdin.read().split("\0") if p))'  # должно быть 0
```

## История

maERP 2026-09-08: правка `СформироватьПоУслугамПереработчика` в
`ВзаиморасчётыСПоставщиками/ManagerModule.bsl` добавлена через `git add` с
набранным путём — в коммит ушёл новый файл на 243 строки, а следующий коммит
(`--amend` не туда) удалил его обратно. Исправлено `git reset --mixed` на
предыдущий коммит и пересборкой трёх коммитов через `git add -u`. Та же причина,
по которой `refcheck.py` нормализует имена в NFC (см. docs/TESTING.md maERP).

maERP 2026-10-09: клон на Windows — 189 путей (88 объектов: регистры взаиморасчётов,
отчёты, общие модули, картинки, макеты драйверов) лежали в индексе в NFD.
Прежняя редакция этого правила («стейджить по отслеживаемому пути») только
закрепляла NFD. Пути переписаны в NFC одним коммитом-переименованием, проверка
добавлена в `scripts/lint.sh`.
