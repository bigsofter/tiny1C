# git add с набранным именем файла с «ё» на macOS создаёт дубликат пути (NFC против NFD)

## Симптом

Коммит правки в модуле с буквой «ё» или «й» в имени каталога показывает в
`git show --stat` весь файл как новый (`243 insertions(+)`), а `git status`
после коммита по-прежнему видит исходный файл изменённым.

## Причина

macOS хранит имена каталогов в разложенном виде (NFD: «е» + комбинирующая
точка), а имя, набранное или сгенерированное в скрипте, приходит составным (NFC).
Для файловой системы это один файл, для git — два разных пути: `git add <NFC>`
кладёт в индекс новый путь с полным содержимым, а отслеживаемый NFD-путь остаётся
незастейдженным.

## Правило

Файлы с «ё», «й» и другими составными буквами в пути стейджить не по набранному
имени, а по отслеживаемому: `git add -u <каталог>` или `git add -A`, либо взять
путь из вывода `git status`/`git ls-files`. Перед пушем свериться, что путь один:

```bash
git ls-files | grep -c 'ВзаиморасчётыСПоставщиками/ManagerModule'   # должно быть 1
```

Если дубликат уже в истории: `git rm --cached <NFC-путь>`, `git add -u`, и
переписать незапушенные коммиты.

## Как проверить

`git show --stat` сразу после коммита: файл с известным путём и малым диффом.
Дубликат виден и в `git ls-files` — два одинаковых на вид пути.

## История

maERP 2026-09-08: правка `СформироватьПоУслугамПереработчика` в
`ВзаиморасчётыСПоставщиками/ManagerModule.bsl` добавлена через `git add` с
набранным путём — в коммит ушёл новый файл на 243 строки, а следующий коммит
(`--amend` не туда) удалил его обратно. Исправлено `git reset --mixed` на
предыдущий коммит и пересборкой трёх коммитов через `git add -u`. Та же причина,
по которой `refcheck.py` нормализует имена в NFC (см. docs/TESTING.md maERP).
