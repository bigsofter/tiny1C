# В модуле объекта «переменная» с именем реквизита — это сам реквизит: присваивание пишет в объект

## Симптом

```
Метод объекта не обнаружен (ПотребностьЗаказаКлиента)
{Документ.ЗаказПокупателя.МодульОбъекта(506)}:Сохраненная = Менеджер.ПотребностьЗаказаКлиента(...)
```

Код рядом выглядит правильным: строкой выше `Менеджер = РегистрыНакопления.ПотребностиПроизводства;`.
Компиляция, BSL LS, CheckConfig и смок молчат.

## Причина

В модуле объекта (документа, справочника) реквизиты шапки доступны по имени без
`ЭтотОбъект.`. Имя, совпадающее с реквизитом, не заводит локальную переменную —
присваивание пишет в реквизит, приводя значение к его типу. Менеджер регистра в
реквизит типа `СправочникСсылка.ФизическиеЛица` превращается в пустую ссылку, и
вызов метода падает. Если значение приводится без ошибки, падения нет вовсе:
объект молча записывается с затёртым реквизитом.

## Правило

Имена локальных переменных в модулях объектов не совпадают с реквизитами шапки
объекта (а в модуле формы — с реквизитами формы). Перед добавлением присваивания
в модуль объекта сверить имя со списком реквизитов в `.mdo`. Для «служебных»
ссылок на менеджеры брать предметные имена (`Потребности`, `МенеджерКарт`), а не
общие (`Менеджер`, `Статус`, `Сумма`, `Комментарий`), — общие имена чаще всего и
оказываются реквизитами.

Неправильно (у документа есть реквизит «Менеджер»):

```bsl
Менеджер = РегистрыНакопления.ПотребностиПроизводства;
Текущая = Менеджер.ПотребностьЗаказаКлиента(ТЧТовары, ТЧМатериалы);
```

Правильно:

```bsl
Потребности = РегистрыНакопления.ПотребностиПроизводства;
Текущая = Потребности.ПотребностьЗаказаКлиента(ТЧТовары, ТЧМатериалы);
```

Намеренное присваивание реквизиту (`Организация = Заказ.Организация;` в
`ОбработкаЗаполнения`) — не нарушение: так заполняется объект.

## Как проверить

Скрипт: для изменённых модулей объектов собрать имена из строк вида `Имя =` и
пересечь со списком реквизитов шапки из `.mdo`; каждое пересечение — либо
намеренное заполнение объекта, либо ошибка. Поймал ошибку сценарий уровня 3,
вызвавший процедуру модуля объекта на проведённом документе.

## История

2026-09-14, maERP. Этап E7 добавил в модуль объекта заказа клиента проверку
базовой потребности при записи проведённого заказа. Три ревью субагентов код
видели, но не заметили, что «Менеджер» — реквизит заказа. Упал сценарий
`ПроведениеЗаказа` на полностью обновлённой базе. В реальной работе проверка
затёрла бы менеджера у каждого проведённого заказа, записанного без
перепроведения. Переменная переименована (2.0.15.17); сверка присваиваний с
реквизитами по трём другим изменённым модулям объектов нашла только намеренные
заполнения.
