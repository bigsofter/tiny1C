# Повторное проведение того же экземпляра документа удваивает движения, если набор не очищен

## Симптом

Документ проведён, остатки сошлись. Тот же объект в памяти проводят второй раз
(`Док.Записать(РежимЗаписиДокумента.Проведение)`; в интерфейсе — повторное «Провести» в уже
открытой форме) — и остаток регистра уходит в минус ровно на объём документа. В таблице движений
по регистратору вместо двух строк расхода лежат четыре: `2, 3, 2, 3`.

Ошибки при этом нет: проведение проходит, платформа ничего не говорит.

## Причина

`ДокументОбъект.Движения` — это коллекция наборов записей, и набор живёт вместе с объектом. После
первого проведения набор держит в памяти записанные движения. Платформа перед `ОбработкаПроведения`
удаляет движения из БАЗЫ, но набор в памяти не чистит.

Код проведения, который добавляет записи (`Набор.ДобавитьРасход()`, `Набор.Добавить()`), дописывает
их к прежним. `Движения.Записать()` кладёт в базу содержимое набора целиком — то есть удвоенное.

Ветка, которая заполняет набор через `Набор.Загрузить(Таблица)`, от этого свободна: `Загрузить`
заменяет содержимое. Поэтому в одной конфигурации один документ ведёт себя правильно, а соседний —
нет, и расхождение выглядит необъяснимым.

## Правило

В `ОбработкаПроведения` наборы движений очищаются ЯВНО, до первой записи:

Неправильно:

```bsl
Процедура ОбработкаПроведения(Отказ, РежимПроведения)
	УстановитьЗаписьВсехРегистров(Движения);   // только ставит Записывать
	СформироватьДвижения(ЭтотОбъект);           // внутри ДобавитьРасход()
	Движения.Записать();
КонецПроцедуры
```

Правильно:

```bsl
Процедура ОбработкаПроведения(Отказ, РежимПроведения)
	Для Каждого НаборЗаписей Из Движения Цикл
		НаборЗаписей.Очистить();
	КонецЦикла;
	УстановитьЗаписьВсехРегистров(Движения);
	СформироватьДвижения(ЭтотОбъект);
	Движения.Записать();
КонецПроцедуры
```

То же правило действует в отмене проведения, когда движения снимаются кодом, а не платформой:
неочищенный набор возвращает движения в базу.

## Как проверить

Сценарий уровня 3, который проводит документ, сверяет остаток, проводит ТОТ ЖЕ объект повторно и
сверяет остаток снова. Сценарий, создающий для второго проведения свежий объект
(`Ссылка.ПолучитьОбъект()`), эту ошибку не ловит — набор у свежего объекта пуст.

Статический анализ, проверка конфигурации и смок-тест форм молчат: код синтаксически верен.

## История

maERP, 2026-09-20. Новый сценарий уровня 3 на передачу в переработку проверял перепроведение и
получил остаток полуфабриката −5 при ожидаемом 0. Сначала искали ошибку в расчёте количества и в
границе чтения остатков — оба оказались верны. Ответ дал дамп движений регистра по регистратору:
четыре строки расхода вместо двух, с теми же количествами.

Соседний документ той же конфигурации перепроводился правильно — и это сбивало с толку дольше
всего. Разница нашлась не в документах, а в способе заполнения набора: одна ветка звала
`Загрузить`, другая `ДобавитьРасход`.
