# В модуле формы нельзя называть переменную именем свойства формы: «Параметры = …» падает при выполнении

## Симптом

Ошибка во время выполнения, не при компиляции:

```
Object field is not writable (Параметры)
{ОбщаяФорма.ФормаПервогоЗапуска.Форма(436)}:Параметры = ...
[ОшибкаВоВремяВыполненияВстроенногоЯзыка, ОшибкаИспользованияВстроенногоЯзыка]
```

BSL LS, EDT и CheckConfig молчат. Смок «открыть все формы» не ловит, если
присвоение стоит в обработчике команды, а не при создании формы.

## Причина

В методе с контекстом формы (`&НаСервере`, `&НаКлиенте`) имя без объявления
сначала ищется среди свойств формы. `Параметры`, `Элементы`, `Команды`,
`ВладелецФормы`, `ИмяФормы` — свойства только для чтения, поэтому первое же
присвоение `Параметры = …` не заводит локальную переменную, а пытается
записать свойство формы. В методе `&НаКлиентеНаСервереБезКонтекста` контекста
нет, и то же имя — обычная локальная переменная.

## Правило

В методах формы с контекстом не называть переменные именами свойств формы.

Неправильно:

```bsl
&НаСервере
Функция ЗаполнитьБазуНаСервере()
	Параметры = Заполнение.ПараметрыЗаполнения();
```

Правильно:

```bsl
&НаСервере
Функция ЗаполнитьБазуНаСервере()
	ПараметрыЗаполнения = Заполнение.ПараметрыЗаполнения();
```

## Как проверить

Поиск по изменённым модулям форм:
`grep -nE "^\s*(Параметры|Элементы|Команды|ВладелецФормы|ИмяФормы)\s*=" Module.bsl`,
для каждой находки — директива ближайшего метода выше: без контекста — законно,
с контекстом — ошибка.

## История

2026-09-15, maERP. Сборка 2.0.14.11 вынесла заполнение базы в общий модуль,
а в форме мастера первого запуска структуру параметров положили в переменную
`Параметры`. Headless-заполнение обработкой шло мимо формы и работало, поэтому
ошибка всплыла только при интерактивном первом запуске у владельца. Остальные
присвоения `Элементы = Форма.Элементы` в формах отчётов проекта стоят в методах
без контекста и ошибкой не являются.
