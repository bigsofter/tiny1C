# Синоним реквизита — подпись не только в его форме

## Симптом

Переименовали синоним реквизита документа, чтобы поле на форме называлось точнее.
После обновления оказалось, что вместе с формой переименовались колонка списка
документов, колонка отчёта и текст автоматического сообщения проверки заполнения —
в том числе там, где новое слово неверно. Проверка конфигурации, линтер и смок
молчат: ни одно имя не изменилось, изменился только текст.

Худший случай — отчёт, где набор данных собран через `ОБЪЕДИНИТЬ ВСЕ` по документам
с разным смыслом одного реквизита. Заголовок берётся от одной из веток, и колонка
над строками закупки подписывается словом из документа продажи.

## Причина

Синоним реквизита — единственный источник подписи для всего, что ссылается на него
без собственного заголовка:

- поле формы объекта без `<title>`;
- колонка динамического списка `Список.<Реквизит>` без `<title>`;
- поле набора данных СКД без `<title>` — включая поле объединения, где источников
  несколько, а заголовок один;
- автоматические сообщения платформы («Поле "…" не заполнено»).

## Правило

Перед переименованием синонима снять список мест, где заголовок наследуется, и
решить по каждому: следовать за реквизитом или получить свой `<title>` на всех
языках конфигурации (урок gf-002).

Поле СКД, чей набор данных объединяет документы с разным смыслом реквизита, всегда
получает явный заголовок — нейтральный, годный для всех веток.

## Как проверить

Снимком по исходникам: для каждого реквизита — его синонимы, для каждого поля формы
и СКД — явный заголовок либо пометка «наследуется от такого-то реквизита». Дифф
снимка до и после правки показывает и переименования, и места, которые поехали следом.

Заголовок в форме и в схеме компоновки хранится **по-разному**, и скрипт, написанный
по образцу формы, молча увидит «заголовка нет» у всех полей отчётов:

```xml
<!-- Form.form -->
<title><key>ru</key><value>Контрагент</value></title>

<!-- Template.dcs -->
<title xsi:type="v8:LocalStringType">
  <v8:item><v8:lang>ru</v8:lang><v8:content>Контрагент</v8:content></v8:item>
</title>
```

## История

2026-09-25, maERP. Владелец решил называть контрагента по смыслу документа: «Клиент»
в продажных, «Поставщик» в закупочных. Разбор до правки показал, что синоним читают
126 полей схем компоновки в 22 отчётах (в «Истории товара» — набор из одиннадцати
веток `ОБЪЕДИНИТЬ ВСЕ` по продажам и закупкам сразу) и 48 полей форм списков и
выбора. Полям `Контрагент` этих отчётов проставили явный нейтральный заголовок на
четырёх языках, и только после этого переименовали синонимы. Первый вариант скрипта
сверки искал в `.dcs` заголовок в формате формы (`key`/`value`) и отчитался, что
заголовков нет ни у одного поля отчётов, — ошибку поймала сверка чисел «изменилось
62» против ожидаемых 91.
