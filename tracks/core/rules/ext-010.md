# Поле добавленного реквизита на заимствованной форме: Объект объявляется в оверлее

Формат - выгрузка Конфигуратора: `Forms/<Форма>/Ext/Form.xml`.

## Симптом

`LoadConfigFromFiles ... -Extension` падает: «Неверный путь к данным: "Объект.ЗаказОплачен"»,
хотя реквизит у объекта расширения заведён. Второй проход загрузки (сначала объект,
потом форма) падает так же.

## Причина

Форма заимствованного объекта - оверлей: в `Ext/Form.xml` два почти одинаковых дерева,
рабочее (изменения расширения, прямо в `<Form>`) и `<BaseForm version="2.21">` (базовая
форма для сравнения, менять нельзя: иначе элемент перестаёт считаться добавленным).
Деревья различаются отступом, поэтому правка по фрагменту часто неоднозначна: целиться по
уникальному контексту (`</ChildItems>`, `<Attributes/>`, `<BaseForm`). У типовых элементов
оверлея `DataPath` нет, они привязаны по имени к реквизитам из `<BaseForm>`. Путь вида
`Объект.<Реквизит>` платформа разрешает только при объявленном реквизите `Объект`.

## Правило

В `<Attributes>` рабочего дерева объявить основной реквизит и привязать поле обычным путём:

```xml
<Attributes>
  <Attribute name="Объект" id="1000002">
    <Type>cfg:DocumentObject.ЗаказКлиента</Type>
    <MainAttribute>true</MainAttribute>
    <SavedData>true</SavedData>
  </Attribute>
</Attributes>
...
<InputField name="Доп_Оплачен" id="50">
  <DataPath>Объект.Доп_Оплачен</DataPath>
</InputField>
```

Так записывает сам Конфигуратор, когда реквизит перетаскивают на заимствованную форму.
Обход без `DataPath` (объявить реквизит формы с тем же именем и повесить элемент без
пути) загружается, но интерфейсом не подтверждён - не предпочитать.

В типовой (не заимствованной) форме у элементов `DataPath` есть: не путать с оверлеем.

## Как проверить

Загрузка из файлов проходит без ошибки; поле видно и пишет значение в реквизит.

## История

2026-10-05, проект на 1С:УНФ, платформа 8.5.1.1529: поле нового реквизита документа не
загружалось, пока `Объект` не был объявлен в оверлее; формат объявления снят с формы,
которую правил Конфигуратор. Имена объектов в примере вымышленные.
