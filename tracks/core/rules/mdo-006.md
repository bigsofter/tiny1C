# Право на команду в разделе бесполезно без права View на подсистему раздела

## Симптом

Новая общая команда размещена в подсистеме-разделе, в роль добавлено право `View` на
`CommonCommand.<Имя>`, конфигурация обновилась без замечаний, а у пользователя с этой
ролью команды нет: нет и самого раздела в панели разделов. У другой роли раздел есть,
а команды в нём нет, потому что ей право на команду не выдали. Проверка конфигурации,
BSL LS и сверка ссылок молчат: с метаданными всё в порядке.

## Причина

У подсистемы в роли свой объект прав — `Subsystem.<Имя>` (и `Subsystem.<Имя>.Subsystem.<Вложенная>`)
с правом `View`. Раздел показывается только ролям, у которых это право есть. Право на
команду открывает команду, но не раздел, в котором она лежит. При `setForNewObjects = false`
(обычное для рабочих ролей) новые объекты — и команда, и подсистема — ролям автоматически не
достаются.

Типичная ошибка рассуждения: выбирать роли для команды по смыслу («кто работает с этими
документами»), а не по тому, кто видит раздел, куда команда помещена.

## Правило

Роли для команды раздела выбирать так:

1. найти роли с `View` на подсистему раздела:
   `grep -n '<name>Subsystem.Производство</name>' Roles/*/Rights.rights`;
2. из них — те, кому команда нужна и у кого есть права на данные, которые она открывает
   (чтение документа списка, добавление — если из списка создают);
3. выдать `View` на команду именно им.

Если команда нужна роли без доступа к разделу — это отдельное решение: либо открыть роли
раздел (право `View` на подсистему, и тогда в разделе появятся и остальные доступные ей
команды), либо разместить команду в разделе, который роль видит.

Неправильно: `View` на `CommonCommand.ЗаказыНаПроизводство` у ролей продаж, у которых нет
`Subsystem.Производство`. Правильно: у ролей, где объект `Subsystem.Производство` с
`View = true` уже есть.

## Как проверить

Машинной проверки нет: платформа принимает любое сочетание прав. Перед коммитом — `grep`
из п. 1 правила по каждой роли, которой выдано право на команду. После обновления базы —
раздел глазами под этими ролями.

## История

2026-09-13, maERP. Общую команду «Заказы клиентов на производство» положили в раздел
«Производство» и выдали ролям с правами на коммерческое предложение, из которого создаются
такие заказы. Ревьюер плана поймал отсутствие прав на команду, а ревью безопасности заметило,
что у этих ролей нет раздела. В главной сессии замечание сначала отклонили с неверной причиной
«у подсистем нет права View». Ревью данных показало по `Rights.rights`: объект
`Subsystem.Производство` есть только у ролей оператора производства и кладовщика — выдача
продажникам ничего не давала, а кладовщик видел раздел без команды. Права перенесены на роли
с доступом к разделу.
