# Присваивание в составной реквизит: проверять состав типов

## Симптом

Запись документа падает «Несоответствие типов» на присваивании ссылки в реквизит составного
типа, и это не ловится статически.

## Причина

Наборы типов у двух реквизитов одного документа могут сильно различаться (в примере
из переноса: одно основание допускает четыре типа, а аналогичный реквизит строки расшифровки
двадцать семь). Найденная по идентификатору ссылка может быть корректной ссылкой своей базы,
но её типа в наборе именно этого реквизита нет.

## Правило

Либо сверять тип заранее, либо защищаться:

```bsl
// ПРАВИЛЬНО
Если Метаданные.Документы.Платёж.Реквизиты.Основание.Тип.СодержитТип(ТипЗнч(Значение)) Тогда
    Объект.Основание = Значение;
Иначе
    // в протокол: тип не допустим
КонецЕсли;
// или присваивание в Попытка с записью в протокол
```

Перед переносом сверять составы типов обоих целевых реквизитов с составом типов источника.

## История

2026-09-25, перенос платёжных документов УТ 10 в БП: присваивание значения, тип которого есть в БП,
но отсутствует в наборе типов этого реквизита, роняло запись всего документа.
