# Журнал регистрации файловой базы: читать как текст, писать подробно

## Симптом

Нужен текст ошибки, а запускать 1С нельзя (рабочую базу держит пользователь) или смоук в песочнице
поведения не воспроизводит. В журнале же сообщение вроде «Недопустимое значение параметра (параметр номер '1')»
без указания, откуда оно.

## Причина

1. Журнал файловой базы лежал в каталоге `1Cv8Log`: `1Cv8.lgf` (индекс/сплиттеры), файлы
   `<ГГГГММДДччммсс>.lgp` (данные журнала) и `.lgx`. Файлы `.lgp` начинаются со строки
   `1CV8LOG(ver 2.0)`, но тексты сообщений `ЗаписьЖурналаРегистрации` лежат в них обычным
   UTF-8.
2. `КраткоеПредставлениеОшибки` не содержит стека вызовов.

## Правило

- Когда платформу запускать нельзя, искать событие по тексту сообщения текстовым поиском в
  `.lgp` (с контекстными строками). Приём проверен на журнале в последовательном формате
  (`1Cv8.lgf` и `.lgp`). Журнал в формате SQLite (`.lgd`) текстовым поиском не проверялся; его,
  судя по формату, нужно читать средствами платформы или SQLite.
- В журнал писать `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`, а не краткое.

```bsl
// НЕПРАВИЛЬНО
ЗаписьЖурналаРегистрации("Обмен", УровеньЖурналаРегистрации.Ошибка,,, КраткоеПредставлениеОшибки(ИнформацияОбОшибке()));
// ПРАВИЛЬНО
ЗаписьЖурналаРегистрации("Обмен", УровеньЖурналаРегистрации.Ошибка,,, ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
```

## Как проверить

`grep` по `1Cv8Log/*.lgp` находит запись по тексту сообщения; в коде - просмотр обработчиков
ошибок: в `ЗаписьЖурналаРегистрации` должно уходить `ПодробноеПредставлениеОшибки`. Только глазами
и поиском.

## История

2026-10-14, расследование на рабочей файловой базе: текст ошибки интеграции нашёлся поиском по
`.lgp`. Краткое представление в том же месте превратило диагноз в угадывание
(«Недопустимое значение параметра (параметр номер '1')» без стека).
