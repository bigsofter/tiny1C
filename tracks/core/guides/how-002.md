# Вывести реквизит, добавленный расширением, полем на заимствованную форму

Формат - выгрузка Конфигуратора: `<Объект>/Forms/<Форма>/Ext/Form.xml`. Как устроен файл
заимствованной формы (стаб, рабочее дерево и `<BaseForm>`, id команд) - ext-011; почему
поле без объявленного `Объект` не грузится - ext-010. Здесь - порядок.

## Шаги

1. Реквизит уже добавлен заимствованному объекту в расширении и расширение загружено в
   копию базы (how-001). Поле ссылается на реквизит шапки объекта: реквизит табличной
   части полем с путём `Объект.<Реквизит>` не показать (forms-002).
2. Взять оверлей формы из этой же базы, а не из чужой выгрузки и не из памяти:
   `1cv8 DESIGNER /F <папка копии> /DumpConfigToFiles <каталог> -Extension "<Имя>"`,
   файл `<Объект>/Forms/<Форма>/Ext/Form.xml`. Если форма в расширение ещё не
   заимствована - заимствовать её в Конфигураторе и выгрузить снова: стаб формы и пара
   записей в `ConfigDumpInfo.xml` появятся сами (ext-011), руками их не собирать.
   Правка из Конфигуратора без выгрузки пропадёт при следующей загрузке (ext-003).
3. В файле два почти одинаковых дерева: рабочее (прямо в `<Form>`) и `<BaseForm>` с
   отступом на уровень больше. Правится только рабочее; `<BaseForm>` не трогать, иначе
   элемент перестаёт считаться добавленным (ext-010). Правку целить по уникальному
   контексту (`<Attributes/>`, `</ChildItems>` перед `<BaseForm`), а не по фрагменту,
   который встречается в обоих деревьях.
4. В `<Attributes>` рабочего дерева объявить основной реквизит `Объект`: тип - объект
   заимствованного документа или справочника, `MainAttribute` и `SavedData` - как в
   примере ext-010. Если `<Attributes/>` пустой - заменить его блоком с объявлением.
5. В нужную группу `ChildItems` рабочего дерева добавить поле `InputField` с именем с
   префиксом расширения и `DataPath` вида `Объект.<Реквизит>`. Номер `id` взять свободный
   по выгрузке этой формы, не придумывать (ext-011; про расчёт максимального id в
   EDT-формах - forms-018).
6. Загрузить полный каталог расширения, применить отдельной командой, выгрузить обратно и
   сравнить с исходниками (how-001, шаги 3-7).
7. Открыть форму в сеансе: поле на месте, значение в нём сохраняется в реквизит.
   Проверку открытием делает клиентский код, не серверный (ext-008).

## Проверка результата

- `LoadConfigFromFiles -Extension` завершился без «Неверный путь к данным».
- В выгрузке обратно у формы: в `<Attributes>` рабочего дерева есть `Объект` с
  `MainAttribute`, у нового поля `DataPath` = `Объект.<Реквизит>`, `<BaseForm>` совпадает с
  тем, что было до правки.
- В сеансе поле видно, введённое значение после записи документа читается из реквизита.

## Где ломается

- «Неверный путь к данным: "Объект.<Реквизит>"» при загрузке - `Объект` в `<Attributes>`
  рабочего дерева не объявлен; загрузка в два прохода (сначала объект, потом форма) не
  помогает (ext-010).
- Поле есть в файле, но на форме не считается добавленным - правка попала в `<BaseForm>`
  вместо рабочего дерева (ext-010).
- Путь указывает на реквизит, которого у объекта нет (реквизит заведён в табличной части,
  а не в шапке) - forms-002.
- После загрузки поле или сам реквизит пропали - загружали неполный каталог либо правку
  Конфигуратора не выгрузили в дерево до загрузки (ext-003).
- Элемент с `id`, который уже занят в форме, - номер брать из выгрузки (ext-011).
- Обход «объявить реквизит формы с тем же именем и повесить элемент без `DataPath`»
  загружается, но интерфейсом не подтверждён - не предпочитать (ext-010).
