# Собрать расширение из исходников и применить его в копии базы

Формат исходников - выгрузка Конфигуратора (`Configuration.xml`, `ConfigDumpInfo.xml`,
каталоги объектов), не проект EDT. Все команды - пакетный Конфигуратор на файловой копии:
`1cv8 DESIGNER /F <папка копии> ... /Out <журнал>`. Факты по каждому шагу лежат в правилах
из поля «правила»; здесь только порядок.

## Шаги

1. Работать на копии базы, не на рабочей. Исходники - полный каталог расширения: загрузка
   приводит расширение к составу каталога, объект, которого в каталоге нет, из расширения
   пропадёт (ext-003). Правку, сделанную в Конфигураторе, сначала выгрузить в этот каталог
   (`DumpConfigToFiles <каталог> -Extension "<Имя>"`), и только потом править файлы.
2. До загрузки сверить два места в исходниках:
   - `ConfigurationExtensionCompatibilityMode` в `Configuration.xml` расширения не выше
     `CompatibilityMode` основной конфигурации (ext-005);
   - исходники чужого или стороннего расширения - сравнить файлы форм с выгрузкой
     расширения из этой же базы, если оно там уже есть (ext-014).
3. Загрузить из файлов:
   `1cv8 DESIGNER /F <папка копии> /LoadConfigFromFiles <каталог исходников> -Extension "<Имя>" /Out <журнал>`.
   Если расширения в базе ещё нет, оно создаётся с нуля; тела модулей переносятся
   (ext-002). Код возврата 0 и пустой журнал ничего не доказывают (ext-001), поэтому
   дальше идут проверки.
4. Применить отдельной командой, не ключом внутри загрузки (workflow-012):
   `1cv8 DESIGNER /F <папка копии> /UpdateDBCfg -Extension "<Имя>" /Out <журнал>`.
   Код 101 - режим совместимости выше основной конфигурации (ext-005).
5. Активировать - только при первом появлении расширения в базе: флажок «Активно» в
   Конфигураторе (Конфигурация, Расширения конфигурации) или в режиме 1С:Предприятие.
   Ключа командной строки для этого не нашли; флажок переживает повторные загрузки
   (ext-004).
6. Доказать состав выгрузкой обратно:
   `1cv8 DESIGNER /F <папка копии> /DumpConfigToFiles <каталог выгрузки> -Extension "<Имя>"`
   и сравнить каталог выгрузки с исходниками (имена, размер, содержимое файлов).
7. Проверить компиляцию серверного контекста (ext-001):
   `1cv8 DESIGNER /F <папка копии> /CheckModules -Extension "<Имя>" -Server /Out <журнал>`.
   Для клиентского кода расширения - отдельный прогон с `-ThinClient`: в наблюдении
   ошибка была видна только в одном из контекстов.
8. Прогнать сценарий в сеансе: хук или обработка расширения делает то, ради чего
   собирали. Компиляция и выгрузка проверяют текст, а не поведение.

Повторные правки: шаги 3, 4, 6, 7, 8. Активация (шаг 5) повторно не нужна.

Вариант с файлом `.cfe` (перенос в другую копию без каталога исходников): из уже
загруженного расширения `1cv8 DESIGNER /F <папка копии> /DumpCfg <файл>.cfe -Extension "<Имя>"`;
в целевой копии `1cv8 DESIGNER /F <папка копии> /LoadCfg <файл>.cfe -Extension "<Имя>"`,
дальше шаги 4-8. Тела модулей и схемы форм в `.cfe` сохраняются; собирать `.cfe` вручную
как ZIP нельзя (ext-015).

## Проверка результата

- Выгрузка обратно (шаг 6) совпадает с исходниками.
- `CheckModules -Extension "<Имя>" -Server` (шаг 7) завершился без ошибок компиляции.
- В списке расширений копии у расширения стоит флажок «Активно»; сценарий в сеансе
  (шаг 8) показывает поведение расширения.

Машинно ловятся только первые два пункта; активность и поведение - человеком или
сценарием.

## Где ломается

- Правка «не видна», а все команды вернули 0: либо ошибка компиляции модуля, которую
  загрузка не проверяет (ext-001), либо расширение неактивно (ext-004). Проверять обе
  причины, а не искать опечатку в тексте.
- `UpdateDBCfg -Extension` вернул 101 - режим совместимости расширения выше, чем у основной
  конфигурации (ext-005).
- После загрузки из расширения исчез объект - в каталоге его не было, загрузка заменила
  состав (ext-003).
- Выгрузка обратно отличается десятками файлов форм, хотя поведение прежнее, - исходники
  стороннего расширения без свойств, которые дописывает платформа (ext-014).
- `.cfe`, собранный архиватором, платформа не принимает: «Неверный формат» или
  «Ожидается файл расширения» (ext-015).
- При открытых сеансах `UpdateDBCfg` со структурными изменениями (новое измерение, ресурс)
  в одном наблюдении падал с кодом 1 из-за исключительной блокировки; чисто кодовые правки
  применялись. Перед применением структурных правок сеансы закрывать.
