# Запустить внешнюю обработку без интерфейса из скрипта

Тонкий клиент `1cv8c`, не толстый `1cv8`: толстый в управляемом приложении обработку по
`/Execute` не открывает (workflow-015). Все пути - свои, в угловых скобках. Подробности
про ключи, окно безопасности и гонку старта - workflow-015; про сборку `.epf` -
workflow-016; откуда брать обработку, которая живёт в справочнике базы, - workflow-014.

## Шаги

1. Обработка готова к запуску без человека: у неё есть основная форма, работа запускается
   из её `ПриОткрытии`; параметр читается из глобального свойства `ПараметрЗапуска` (строка
   из ключа `/C`); результат выводится через `Сообщить()`; в конце -
   `ЗавершитьРаботуСистемы(Ложь)`, чтобы клиент закрылся сам.

   ```bsl
   &НаКлиенте
   Процедура ПриОткрытии(Отказ)
       Параметр = ПараметрЗапуска;          // строка из /C"..."
       Сообщить("старт: " + Параметр);
       ВыполнитьНаСервере(Параметр);        // работа - серверным вызовом
       Сообщить("готово");
       ЗавершитьРаботуСистемы(Ложь);
   КонецПроцедуры
   ```

2. Собрать `.epf` (или взять готовый). Сборка из файлов BSL не компилирует, а без
   `Ext/ObjectModule.bsl` конфигуратор зависает (workflow-016) - ошибки модулей всплывут
   только на шаге 4. Если обработка подключена в базе через «Дополнительные отчеты и
   обработки» - файл выгружается из элемента справочника, а не из конфигурации
   (workflow-014).
3. Команда запуска из скрипта (логин и пароль - только если у базы они заданы; маска -
   строка соединения своей проверочной базы, не `.*`):

   ```
   1cv8c ENTERPRISE /F <папка копии> /N <пользователь> /P <пароль, если задан> /Execute <файл>.epf /C"<параметр>" /DisableStartupDialogs /DisableStartupMessages /DisableUnsafeActionProtection "<маска строки соединения>" /Out <журнал>
   ```

   Без `/DisableUnsafeActionProtection` после обновления конфигурации клиент встаёт на
   окне «Предупреждение безопасности» и ждёт щелчка до таймаута (workflow-015).
4. Скрипт ждёт завершения процесса с таймаутом, затем читает журнал `/Out` и код
   возврата. Два клиента на одной файловой базе стартуют с разносом в несколько секунд,
   одновременность самой работы - файлом-барьером (workflow-015).
5. Правка обработки - пересобрать `.epf` и повторить шаги 3-4; первая ошибка BSL видна
   только при прогоне (workflow-016).

## Проверка результата

- В журнале `/Out` есть строки, которые обработка выводит в начале и в конце (в примере -
  «старт: ...» и «готово»), и переданный параметр читается в первой из них.
- Процесс клиента завершился сам до таймаута скрипта.
- Если обработка пишет файл-результат - он на месте с ожидаемым содержимым.

## Где ломается

- Процесс висит до таймаута, журнал пуст - окно «Предупреждение безопасности»; снять окно
  клиента снимком и прочитать журнал (workflow-015).
- Клиент завершился сразу, в журнале ни строки - запущен толстый `1cv8` вместо `1cv8c`
  (workflow-015).
- «Ошибка разделения доступа к базе данных ... 1Cv8tmp.1CD» у второго клиента - два
  клиента стартовали в одну секунду (workflow-015).
- «Ошибка инициализации модуля ... Неопознанный оператор» при первом запуске - сборка
  `.epf` не компилирует BSL (workflow-016).
- Правка «не доехала»: в базе исполняется старая обработка из элемента справочника
  «Дополнительные отчеты и обработки», а новый файл в тот же элемент не загружен
  (workflow-014).
